# 01 · Понятия

Семь понятий, на которых стоит всё остальное. Прочитав их, можно открывать любой раздел документации и понимать, о чём он.

## Движок и сайт — отдельно

**Движок** — это программа `heron`, которая приходит образом `ghcr.io/fmstm/heron:<тег>` или pip-пакетом. Её не копируют в сайт и не правят под сайт.

**Сайт** — папка, в которой нет ни строчки кода движка:

```
мой-сайт/
├── site.yaml       конфиг: домен, языки, тема, меню, SEO-настройки
├── content/        страницы в markdown, по папке на язык
├── media/          картинки, видео, документы
├── data/           yaml-справочники: отзывы, команда, реквизиты
├── static/         файлы по точному адресу: favicon, .well-known
├── theme/          тема: шаблоны Jinja2, стили, строки интерфейса
└── plugins/        свои плагины, обычно пусто
```

Сайт объявляет, какой движок ему нужен, первой строкой `site.yaml`: `heron: ">=0.1,<0.2"`. Один движок обслуживает любое число сайтов, у каждого сайта может быть своя версия.

→ Подробно: [`20` §0–1](../spec/20-data-contract.md#0-что-это-за-система)

## Контракт

Контракт — договор между движком и папкой сайта: какие файлы где лежат, какие поля у страницы, какие ключи у `site.yaml`, что движок сделает сам и на что ответит ошибкой. Он один для всех сайтов и записан в [`docs/spec/20-data-contract.md`](../spec/20-data-contract.md). Нарушение контракта — внятная ошибка с кодом, файлом и строкой (`E002`, `E006`…), а не молча сломанная страница.

## Страница, ключ и адрес

**Страница — это markdown-файл.** Путь файла задаёт адрес:

```
content/uk/index.md                →  /
content/uk/about.md                →  /about/
content/uk/services/_index.md      →  /services/          страница самого раздела
content/uk/services/design.md      →  /services/design/
content/ru/services/design.md      →  /ru/services/design/
```

У страницы две разные вещи, которые по умолчанию совпадают:

- **ключ** — путь файла без `.md`: `services/design`. По нему движок связывает переводы, по нему страницу называют в меню и в ссылках;
- **адрес** — то, что видит посетитель. Его можно поменять полем `slug`, ключ при этом не меняется.

Главная — `index.md`, её ключ `/`. Страница «не найдено» — `404.md`.

→ Подробно: [`20` §2](../spec/20-data-contract.md#2-дерево-контента-и-url)

## Языки

Язык — папка в `content/`. Язык по умолчанию отдаётся из корня, остальные — с префиксом `/<язык>/`. Перевод — файл с тем же именем в папке другого языка; адрес у него может быть свой (`slug`). Список языков задаёт `site.yaml`.

→ Подробно: [`20` §3](../spec/20-data-contract.md#3-языки)

## SEO-блок и фронтматтер

Каждый файл страницы начинается с **SEO-блока** — YAML между `---`, разбитого на восемь групп с комментариями: основное, ключевые запросы, Open Graph, Twitter, schema.org, карточка, служебное, связи. Обязательны три поля: `title`, `h1`, `description`. Остальное — по мере надобности, пустые поля остаются закомментированными.

Стартовые страницы приходят с полным блоком, `heron page` кладёт его в каждую новую. Новая страница — копия файла с правкой значений.

→ Подробно: [`20` §4.1–4.2](../spec/20-data-contract.md#41-общий-вид)

## Секции и их формы

После SEO-блока — текст. Текст до первого заголовка — вступление. Дальше — **секции**:

```markdown
## Как мы работаем {#how}

1. **Заявка.** Пишете или звоните.
2. **Встреча.** Обсуждаем задачу.
```

`{#how}` — якорь, адрес секции для темы. Порядок секций в файле не важен: тема ставит каждую на своё место по якорю. **Форму** секции движок понимает по разметке: нумерованный список — шаги, `### Вопрос?` — FAQ, `ключ | значение` — факты, таблица — таблица. Всего форм двенадцать.

→ Подробно: [`20` §4.3–4.4](../spec/20-data-contract.md#43-секции)

## Тип страницы и тема

**Тема** — папка `theme/`: шаблоны Jinja2, модули, стили, строки интерфейса. Она решает, как выглядит сайт; контент решает, что на нём написано.

**Тип страницы** выбирает шаблон: страница типа `service` рисуется `theme/templates/service.html`. Тип задаётся полем `type` в файле или `children_type` в `_index.md` раздела, у главной — `home`, по умолчанию — `page`. В `theme/theme.yaml` тема описывает свои типы, их секции, связи между страницами и пропорции картинок.

→ Подробно: [`20` §6](../spec/20-data-contract.md#6-themeyaml), [гайд по теме](04-theme.md)

## Сборка

`heron build` читает папку, проверяет её по контракту и собирает `dist/`: HTML страниц, `sitemap.xml`, `robots.txt`, `llms.txt`, разметку JSON-LD, нарезанные картинки, карты 301/410 и конфиг nginx. Дев-сборка (по умолчанию) закрыта от поисковиков; боевая — `--env prod`. Результат — либо папка на любой хостинг, либо образ nginx с сайтом внутри.

→ Подробно: [`21` §4](../spec/21-engine.md#4-конвейер-сборки), [гайд по выкладке](06-deploy.md)
