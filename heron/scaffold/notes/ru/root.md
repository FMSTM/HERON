# {name}

Контент сайта на движке [HERON](https://github.com/FMSTM/HERON). Здесь только
контент: тексты, медиа, тема, конфигурация. Сборкой, окружениями и упаковкой
в образ занимается HERON — ни Dockerfile, ни compose, ни `.env` в этой папке
нет и быть не должно.

## С чего начать

`site.yaml` — единственная точка правды о сайте: домен, языки, тема, меню,
версия движка. Структура папок следует за конфигом, а не наоборот: дописали
язык в `languages`, выполнили `init` — под него появились `content/<язык>/`
и `theme/i18n/<язык>.yaml`.

Пароли и токены в `site.yaml` не пишут: сборка статическая, и всё, что она
видит, может оказаться в HTML.

## Что где лежит

| Папка | Что внутри |
|---|---|
| `content/<язык>/` | страницы в markdown, путь файла = адрес страницы |
| `media/` | всё, что показывает контент: изображения, видео, документы |
| `theme/` | как сайт выглядит: шаблоны, стили, строки интерфейса |
| `data/` | сквозные справочники в yaml, доступны шаблонам как `data.<имя>` |
| `static/` | файлы, которые обязаны лежать по точному адресу |
| `plugins/` | расширения сборки для этого сайта |

В каждой папке лежит `heron-readme.md` — короткая записка о том, что класть
туда и чего не класть. Движок эти файлы не замечает и в сайт не тащит.

## Порядок работы

Из папки HERON:

```bash
./scripts/site.sh {slug} init          # папки догоняют site.yaml
./scripts/site.sh {slug} build dev     # собрать
./scripts/site.sh {slug} serve dev     # посмотреть на localhost:8080
./scripts/site.sh {slug} stop  dev
```

Контента может не быть вовсе — пустой сайт собирается и отдаёт robots.txt
и карту сайта. Тему можно доводить, ещё не написав ни одной страницы.
