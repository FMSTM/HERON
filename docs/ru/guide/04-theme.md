# 04 · Тема и дизайн

В этом разделе - как устроена тема, как сделать свою и какие данные получает шаблон. Он для того, кто отвечает за внешний вид сайта: дизайнера, верстальщика или AI-агента в роли дизайнера.

Сайт на HERON делится на две независимые части. **Тема** решает, как сайт выглядит: шаблоны, стили, шрифты. **Контент** решает, что на нём написано: тексты страниц в `content/`. Тема не знает ни одного текста страницы, а контент не знает ни одного класса CSS. Встречаются они по именам: тип страницы находит свой шаблон, а якорь секции - свой модуль. Поэтому тему можно заменить, не трогая тексты, и наоборот.

> **Команды в разделе написаны для Docker** и запускаются из папки сайта (`cd ~/sites/мой-сайт`), поэтому путь к сайту в них - точка. Поставили движок без Docker - замените всё до имени образа (`ghcr.io/fmstm/heron:…`) включительно словом `heron` ([подробнее](00-install.md#without-docker)).

## Откуда взять тему

Есть три пути:

- **Стартовая тема** уже лежит в каждом новом сайте после `new`. Она белая, со светлым и тёмным режимом и умеет показывать все тринадцать форм секций. С ней приходят демонстрационные страницы на украинском, русском и английском: главная, «Блоки» (все виды блоков на одной странице), «Темы», «Документация», раздел «Структура» с двумя страницами внутри и страница 404. Если вы поменяли тему и хотите вернуть стартовую, выполните `theme get starter .`.
- **Тема из каталога** ставится по имени: `theme get <имя> .`. Посмотреть каталог - `theme list`. Сейчас в нём только `starter`.
- **Тема по ссылке или из архива**: `theme get https://…/theme.tar.gz .` или `theme get ./theme.zip .`.

Чтобы передать свою тему на другой сайт, упакуйте её в архив: `theme pack . --out theme.tar.gz`. В архив попадают тема и контент сайта - контент станет демонстрационными страницами темы. Поэтому тема упаковывается, только если контент показывает всё, что она умеет ([«Демо темы и справка»](#theme-demo)). Без `--out` архив ляжет в `dist/theme.tar.gz`.

Те же команды целиком:

```bash
docker run --rm ghcr.io/fmstm/heron:prod theme list
docker run --rm -v "$PWD:/site" -w /site --user "$(id -u):$(id -g)" ghcr.io/fmstm/heron:prod theme get starter .
docker run --rm -v "$PWD:/site" -w /site --user "$(id -u):$(id -g)" ghcr.io/fmstm/heron:prod theme pack . --out theme.tar.gz
```

При установке новой темы старая не пропадает: она уезжает в `.heron-cache/setup/`, и движок пишет, куда именно. Страницы сайта не перезаписываются: демонстрационные страницы новой темы кладутся только туда, где файла ещё нет. Движок перечислит каждый разложенный файл и скажет, сколько файлов оставил как есть, потому что они у сайта уже были. Что можно класть в архив темы, а что нельзя, - [`21` §10](../spec/21-engine.md#heron-theme).

## Из чего состоит тема

Тема - это папка `theme/` внутри папки сайта:

```
theme/
├── theme.yaml            паспорт: типы страниц, их секции, связи, картинки
├── base.html             каркас: <head>, шапка, подвал, блок content
├── templates/            по шаблону на тип: home.html, page.html, service.html, 404.html…
├── modules/              по файлу на модуль: prose.html, steps.html, faq.html…
├── partials/             куски каркаса: header.html, footer.html, analytics.html
├── assets/               CSS, JS, шрифты - копируются в dist как есть
└── i18n/<язык>.yaml      строки интерфейса: en.yaml, ru.yaml - «Read more» / «Читать далее»
```

Стартовая тема, которую кладёт `new`, содержит типы страниц `home`, `page` и `404` и по модулю на каждую форму секции: `prose`, `list` (он же рисует `alert-list`), `checklist` (и `two-lists`), `steps`, `table`, `facts`, `faq`, `timeline`, `callout`, `gallery`, `tabs`. Ещё два модуля - `breadcrumbs` (хлебные крошки) и `children` (карточки дочерних страниц раздела). Какой модуль рисует какую секцию, решает `partials/sections.html`. Вкладки работают без скриптов, на радиокнопках. Свою тему проще всего начать с копии стартовой: поменяйте переменные в начале `assets/site.css` (цвета, шрифты, отступы) и расставьте секции по якорям в `templates/`.

## Паспорт темы: `theme.yaml`

`theme.yaml` описывает, какие страницы тема умеет показывать и что ей для этого нужно. Пример:

```yaml
name: main
version: "1.0"

requires: [contact.phone, organization.name]   # что тема берёт из site.yaml

modules: [breadcrumbs, prose, facts, list, steps, faq, cards]

types:
  home:
    uses: [intro, about, services, faq]
  service:
    uses: [intro, quick-facts, what, "how:steps", faq]
    jsonld: [Service]
  page:
    uses: [intro, "*"]            # "*" - любые секции

links:                            # связи между страницами
  - field: related
    type: service
    back: mentioned_in

images:
  widths: [400, 800, 1200, 1600]
  ratios: ["1:1", "16:9"]
  formats: [avif, webp]
```

Что значат ключи:

- **`types.<тип>.uses`** - какие секции показывает страница этого типа. Это договор с контентом. Команда `page service roof мой-сайт` (в теме, где есть тип `service`, как в примере выше) положит в новую страницу заготовки ровно этих секций, а сводка «Не заполнено» после сборки назовёт пустые. Если в файле страницы есть секция, которой нет в `uses`, в отчёте появится строка - так ловится опечатка в якоре. Запись `"how:steps"` значит, что тема ждёт у секции `how` форму `steps` (нумерованные шаги).
- **`requires`** - пути в `site.yaml`, без которых тема не работает, например телефон в шапке. Не заполнены - сборка остановится с ошибкой `E011` ещё до отрисовки страниц.
- **`links`** - поля, которыми страницы ссылаются друг на друга. Движок сам найдёт страницы по этим полям, проверит, что они существуют, и построит обратный список (`back`): у услуги появится перечень статей, где она упомянута. `type` ограничивает, **на страницы какого типа** ведёт поле: `related` с `type: service` не свяжет статьи между собой. Связь без ограничения пишется без `type`: `- {field: related, back: related_from}`.
- **`images`** - как нарезать картинки: ширины, пропорции, форматы. Там же `fallback_width` - ширина запасного PNG/JPEG для старых браузеров, `cover_width` - ширина обложки для поисковиков и соцсетей, `crop` и `as_is` - пути картинок, которые нужно обязательно обрезать или скопировать без нарезки. Нарезается только то, что шаблоны действительно попросили.
- **`types.<тип>.template`** - если тип рисуется не файлом `templates/<тип>.html`, а другим: путь от `templates/`.
- **`forms`** - формы, которые рисует тема; их описание обязано быть в `site.yaml`, иначе `E011`.
- **`heron`** - на какую версию движка рассчитана тема. Версия не та - ошибка `E012`.

Каждый ключ подробно - [`20` §6](../spec/20-data-contract.md#theme-yaml).

## Поля блоков и подсказки <a id="block-fields"></a>

Шаблоны объясняют движку, как страница выглядит. Но человеку, который будет её заполнять, этого мало: ему нужно знать, какие блоки есть у страницы, что писать в каждое поле и как это скажется на сайте и в поиске. Это тоже пишется в `theme.yaml` - как описание полей и подсказки. По нему работают опросник и студия, по нему агент заполняет страницы, не читая шаблонов, а `heron check` следит, чтобы описание было полным.

Описание необязательно. Тема без него собирается как раньше, только `heron check` один раз предупредит, что опросник и студия покажут лишь SEO-блок. Стартовая тема описана полностью - загляните в её `theme.yaml`, это лучший образец.

Как описать блок, на примере вопросов и ответов:

```yaml
languages: [ru, en]              # на каких языках вы пишете подсказки

modules:
  faq:
    kinds: [faq]                 # какую форму секции рисует модуль (таблица 20 §4.4)
    hint_ru: Вопросы и ответы - вопрос заголовком, ответ под ним
    hint_en: Questions and answers - the question as a heading, the answer under it
    help_ru: Вопрос - заголовок третьего уровня, ответ - текст под ним; в поиске блок размечается как FAQPage
    help_en: |-
      Every question is a third-level heading, the answer is the text under it.
      In search the block is marked up as FAQPage.
    fields:
      - name: items
        type: list
        required: true
        md: groups               # группы ### в markdown
        hint_ru: Пары вопрос - ответ
        hint_en: Question - answer pairs
        fields:
          - {name: q, type: text, required: true, md: heading, max_length: 120, hint_ru: Вопрос, hint_en: The question}
          - {name: a, type: markdown, required: true, md: content, hint_ru: Ответ, hint_en: The answer}
```

Что здесь важно:

- **Поля описывают настоящий markdown.** `md` говорит, где значение лежит в файле: `heading` - текст заголовка `###`, `content` - всё под ним, `items` - пункты списка, `bold` - жирный зачин пункта. Словарь мест один на все темы, он есть в [`21` «Контракт темы»](../spec/21-engine.md#theme-contract). Не придумывайте свою модель данных: опишите то, что человек и так пишет в файле, иначе опросник не сможет записать значение обратно.
- **`hint` обязателен на каждом языке темы**: у каждого типа, секции, модуля, поля и вида категории. Это одна строка, которую человек увидит при наведении. Не хватает хотя бы одной - `heron check` остановится с `E008` и перечислит, где именно.
- **`help` - для новичка.** Напишите, что это за блок, на что он влияет на сайте и в поиске, хороший пример и частые ошибки. У модуля можно добавить `example_ru` и `example_en` - образец markdown, его покажет `heron describe <имя>`.
- **Служебные поля писать не нужно.** `title`, `h1`, `description`, адрес, обложку, меню, `noindex` описывает сам движок, с подсказками на ru и en.

Секции типа описываются рядом с `uses`: обязательна ли секция и какая подсказка к ней. Если страницы типа бывают категорией (папкой с `_index.md`), назовите тип страниц внутри и виды, которыми категория их показывает:

```yaml
types:
  page:
    uses: [intro, "*"]
    hint_ru: Обычная страница
    hint_en: An ordinary page
    children_type: page          # тип страниц внутри категории
    views:
      key: view                  # строка view: list во фронтматтере _index.md
      default: cards
      options:
        cards: {hint_ru: Карточки сеткой, hint_en: Cards in a grid}
        list: {hint_ru: Список строками, hint_en: A list of rows}
    sections:
      intro: {required: true, hint_ru: Вводный абзац, hint_en: The intro paragraph}
```

Виды придумывает тема - ровно те, что рисуют её шаблоны. В стартовой теме модуль `children` читает `page.meta.get('view')` и показывает страницы карточками или списком.

Посмотреть, что получилось, - командой `describe`. Без имени она коротко покажет всё описание вместе со служебными полями и значениями из `site.yaml`, с именем блока или типа - его одного с подробной справкой, с `--json` - то же для агента:

```bash
docker run --rm -v "$PWD:/site" -w /site --user "$(id -u):$(id -g)" ghcr.io/fmstm/heron:prod describe
docker run --rm -v "$PWD:/site" -w /site --user "$(id -u):$(id -g)" ghcr.io/fmstm/heron:prod describe faq
docker run --rm -v "$PWD:/site" -w /site --user "$(id -u):$(id -g)" ghcr.io/fmstm/heron:prod describe --json --lang en
```

Все ключи описания - [`21` «Контракт темы»](../spec/21-engine.md#theme-contract), форма вывода `describe --json` - [`21` §10](../spec/21-engine.md#heron-describe).

## Демо темы и справка <a id="theme-demo"></a>

Демо - это не украшение темы, а её образец подачи: какие страницы нужны сайту такой тематики, какие блоки на них и в каком порядке. Автор темы продумывает эту структуру один раз, а тот, кто ставит тему, получает её готовой и заменяет тексты своими. Поэтому демо обязательно и показывает всё, что объявил `theme.yaml`:

- **каждый тип страницы** - хотя бы одна страница этого типа: главная, обычная страница, 404 и любой свой тип;
- **каждый блок** - модуль что-то нарисовал хотя бы на одной странице, в том числе модули страницы (`breadcrumbs`, `children`);
- **каждый вид раздела** - страница раздела (папка с `_index.md` и страницами внутри), у которой стоит `view: <вид>`, а для вида по умолчанию - без этой строки.

Демо темы - это контент сайта, из которого её упаковывают. Проверить его можно, не упаковывая, командой `check . --theme`: движок соберёт страницы шаблонами темы и перечислит, чего не хватает. Тот же список останавливает `theme pack` с ошибкой `E037`, и архив не создаётся. У старой темы без описания полей неполное демо - только предупреждение. Обычная проверка `check .` демо не требует: на своём сайте вы вправе удалить ненужные демонстрационные страницы.

**Справка темы** собирается из `theme.yaml` и демо сама, руками её не пишут: типы страниц с секциями, каждый блок с подсказкой и полями, рядом - живой пример из демо и его исходный markdown, виды разделов со строкой, которая их включает, разметка schema.org, переменные стилей и строки интерфейса. Поменяли контракт или демо - поменялась и справка. Посмотреть её можно двумя способами:

```bash
docker run --rm -v "$PWD:/site" -w /site --user "$(id -u):$(id -g)" ghcr.io/fmstm/heron:prod docs theme-ref .
docker run --rm -it -p 127.0.0.1:8000:8000 -v "$PWD:/site" -w /site --user "$(id -u):$(id -g)" ghcr.io/fmstm/heron:prod serve .
```

Первая команда печатает справку текстом в терминале: примеры там - исходный markdown и файл, где он лежит. Вторая запускает просмотр сайта: откройте в браузере `localhost:8000/_heron/theme/` - там та же справка с живыми примерами в стилях темы, на других языках сайта - `/_heron/theme/<язык>/`. Эта служебная страница есть только в черновой сборке и в просмотре: в боевую сборку (`--env prod`), в карту сайта и в поиск она не попадает.

## Шаблон типа страницы

Каждый тип страницы рисуется своим шаблоном: тип `service` - файлом `templates/service.html`. Шаблон читается сверху вниз, в том же порядке блоки окажутся на странице:

```jinja
{% extends "base.html" %}
{% block content %}
  {{ mod.breadcrumbs() }}
  <h1>{{ page.h1 }}</h1>
  {{ mod.facts('quick-facts') }}
  {{ mod.prose('what') }}
  {{ mod.steps('how') }}
  {{ mod.faq('faq') }}
  {% for p in page.related.get('related', []) %}
    <a href="{{ p.url }}">{{ p.h1 }}</a>
  {% endfor %}
{% endblock %}
```

`mod.prose('what')` берёт из страницы секцию с якорем `what` и рисует её модулем `prose`. Главное правило: **нет секции - нет ничего**. Если у страницы нет секции `what`, на её месте не будет ни заголовка, ни пустой рамки, и проверять это условиями не нужно. Поэтому порядок секций в файле контента не важен, а страница, где каких-то секций не хватает, вёрстку не ломает.

Бывает, что шаблон заранее не знает, какие секции придут, - например, у обычной текстовой страницы. Тогда модуль выбирают по форме секции. Так устроен `partials/sections.html` стартовой темы (в самом файле перечислены все формы):

```jinja
{% for section in page.sections.values() %}
  {% if section.kind == 'faq' %}{{ mod.faq(section.id) }}
  {% elif section.kind == 'steps' %}{{ mod.steps(section.id) }}
  {% else %}{{ mod.prose(section.id) }}{% endif %}
{% endfor %}
```

Модуль ждёт свою форму данных. Если вызвать `mod.steps('how')`, а в секции `how` обычный текст, сборка упадёт с `E010` (`'str object' has no attribute ...`), и в сообщении будет назван шаблон, а не модуль. Поэтому строку отчёта «ждали steps, пришло prose» исправляют до сборки. А если контент может прийти в разной форме, модуль выбирают по `section.kind`, как в примере выше.

### Пути и макросы

- **Пути в `extends`, `include` и `import` считаются от корня темы**, а не от папки, где лежит шаблон: `{% extends "base.html" %}`, `{% extends "templates/page.html" %}`, `{% include "partials/header.html" %}`. Если из `templates/landing.html` написать `{% extends "page.html" %}`, будет ошибка `E008` с подсказкой, где файл на самом деле.
- **`mod` доступен в каждом шаблоне** - импортировать модули не нужно. Со своими макросами иначе: `{% import %}` в `base.html` дочерним шаблонам не виден (так устроен Jinja2), поэтому импортируйте их в каждом шаблоне, где они нужны.

## Что вывести в `<head>` <a id="head-seo"></a>

Каркас `base.html` отвечает за всё, что поисковик и мессенджер читают раньше самой страницы. Чтобы работали картинки в выдаче и превью ссылок, в `<head>` нужны три вещи:

- `<meta name="robots" content="{{ robots_meta }}">`. Открыта страница для поисковиков или закрыта, решает не тема, а движок: он кладёт в `robots_meta` готовую строку. Без этой строки крупные превью в выдаче не включатся, а закрытая черновая сборка не получит `noindex`;
- `og:image` и `twitter:image` - адрес обложки из `cover_url(page)`. Выводите их, только когда адрес не пустой: пустая строка значит, что обложки нет, а пустой тег хуже отсутствующего;
- размеры и подпись картинки: `page.cover.width`, `page.cover.height`, `page.cover.alt`. По размерам соцсеть показывает превью сразу, не скачивая картинку, а `alt` нужен тем, кто картинку не видит.

Пример блока целиком - так он устроен в стартовой теме:

```jinja
<title>{{ page.title }}{{ site.seo.title_suffix }}</title>
<meta name="description" content="{{ page.meta.description }}">
<link rel="canonical" href="{{ absolute(page.url) }}">
<meta property="og:title" content="{{ page.meta.og_title or page.title }}">
<meta property="og:description" content="{{ page.meta.og_description or page.meta.description }}">
{% set cover = page.cover %}
{% set cover_src = cover_url(page) if cover else "" %}
{% if cover_src %}
<meta property="og:image" content="{{ cover_src }}">
{% if cover.width %}<meta property="og:image:width" content="{{ cover.width }}">{% endif %}
{% if cover.height %}<meta property="og:image:height" content="{{ cover.height }}">{% endif %}
{% if cover.alt %}<meta property="og:image:alt" content="{{ cover.alt }}">{% endif %}
<meta name="twitter:image" content="{{ cover_src }}">
{% endif %}
<meta name="robots" content="{{ robots_meta }}">
{% for code, href in hreflang %}<link rel="alternate" hreflang="{{ code }}" href="{{ href }}">{% endfor %}
{% set ld = jsonld() %}
{% if ld %}<script type="application/ld+json">{{ ld }}</script>{% endif %}
```

Имена `cover_url` и `robots_meta` заняты движком: не заводите в теме свои переменные с такими именами. Какая картинка становится обложкой и как её подготовить - [05 · SEO](05-seo.md#you-fill), точные правила выбора - [`20` §6](../spec/20-data-contract.md#page-cover).

## Модуль

Модуль рисует одну секцию. Это файл `modules/<имя>.html`, а вызывается он из шаблона как `mod.<имя>(<якорь>)`. Внутри модуля доступны:

| Переменная | Что это |
|---|---|
| `section` | секция: `id`, `title`, `kind`, `lead`, `body`, `note` (абзацы после основного узла), `note_title`, `callout`, `links` |
| `items` | разобранные данные формы: шаги, пары вопрос-ответ, факты… |
| `html` | готовая вёрстка всего содержимого секции |
| всё, что видит шаблон | `page`, `site`, `t`, `picture`… |

Например, модуль вопросов и ответов:

```jinja
<section id="{{ section.id }}" class="faq">
  {% if section.title %}<h2>{{ section.title }}</h2>{% endif %}
  {% for pair in items %}
    <details><summary>{{ pair.q }}</summary>{{ pair.a|safe }}</details>
  {% endfor %}
</section>
```

Что лежит в `items` у каждой из тринадцати форм, - таблица [`20` §4.4](../spec/20-data-contract.md#section-forms). Модули без аргумента, например `mod.breadcrumbs()`, берут данные не из секции, а из `page` и `site`.

## Что видит шаблон

Всё, что шаблон может использовать:

| Имя | Что это |
|---|---|
| `page` | страница: `h1`, `title`, `url`, `type`, `intro`, `sections`, `children`, `parent`, `breadcrumbs`, `translations`, `related`, `meta.<поле>` |
| `site` | весь `site.yaml`, значения уже на языке страницы: `site.site.name`, `site.contact.phone` |
| `data` | содержимое `data/*.yaml` |
| `nav` | меню из `site.yaml`, уже страницами: `item.url`, `item.nav_title` |
| `t` | строки интерфейса текущего языка: `t.read_more` |
| `lang`, `languages`, `hreflang` | текущий язык, все языки, адреса переводов |
| `page_of(key)` | страница по ключу на текущем языке; главная - `page_of('/')` |
| `picture(src, ratio)` | готовый `<picture>` с `srcset`, WebP/AVIF и размерами |
| `media_url(src, ratio, width)` | адрес одной нарезки |
| `jsonld()` | разметка JSON-LD страницы, вставить в `<head>` |
| `cover_url(page, min_width=1200)` | абсолютный адрес обложки шириной не меньше `min_width`; обложки нет - пустая строка. Есть и фильтр: `{{ page|cover_url }}` |
| `robots_meta` | строка для `<meta name="robots">`: крупные превью на индексируемой странице боевой сборки (prod), `noindex, nofollow` на закрытой |
| `env` | окружение сборки: `env.indexable`, `env.analytics` |
| `theme` | `theme.yaml` моделью: `theme.types`, `theme.images` |
| `pages` | весь сайт: все страницы всех языков (`pages.of_lang('ru')`, `pages.of_type('article', 'ru')`, `pages.by_url`); страница по ключу удобнее через `page_of` |
| `absolute(url)` | абсолютный адрес на домене сборки; есть и фильтр `{{ url|absolute }}` |

Полная модель страницы - [`21` §6](../spec/21-engine.md#page-model), все переменные - [`21` §7](../spec/21-engine.md#rendering).

Если шаблон обращается к переменной, которой нет, **сборка останавливается** с ошибкой `E010`, именем страницы и шаблона, а не выводит молча пустоту. Так опечатка в теме ловится сразу, а не на живом сайте.

### Свои поля страницы

Тема может ждать в SEO-блоке страницы свои поля - например, `topic` или `eyebrow` (надзаголовок). Объявлять их нигде не нужно: движок кладёт их в страницу как есть.

```jinja
{% if page.meta.get('eyebrow') %}<p class="eyebrow">{{ page.meta.get('eyebrow') }}</p>{% endif %}
<span>{{ page.meta.get('topic', 'general') }}</span>
```

Читайте свои поля через `page.meta.get('поле', запасное)`: так шаблон не падает, если у страницы поля нет. А `page.meta.topic` упадёт - это сделано нарочно, чтобы ловить опечатки в полях самого движка. Все свои поля страницы разом - `page.meta.extra`.

Ключ `fields` в `theme.yaml` - **только для полей движка**, которые тема ждёт от новой версии движка. Свои поля туда не пишут: движок их не знает и ответит ошибкой `E023`.

### Значения на языке страницы

Шаблон получает `site.yaml` уже на языке страницы - **все блоки, на любой глубине**. На русской странице `site.contact.address` - это значение `address_ru`, `site.site.name` - `name_ru`, `site.organization.about` - `about_ru`. Если ключа для языка нет, берётся ключ без языкового суффикса (`_ru`). Выбирать язык фильтром не нужно, хотя ключи с суффиксом тоже доступны.

То же правило работает в подстановках разметки для поисковиков (`{{ contact.address }}` в блоке `schema`), поэтому адрес в подвале и в разметке всегда совпадает.

## Накопление данных в шаблоне без `append` <a id="accumulate-data-without-append"></a>

Шаблоны темы выполняются в защищённой среде, где данные нельзя менять ([`21` §7](../spec/21-engine.md#rendering)). Методы, которые меняют список или словарь, - `.append`, `.extend`, `.insert`, `.update`, `.pop`, `.remove`, `.add`, `.setdefault`, `.clear`, `.sort`, `.reverse` - останавливают сборку с ошибкой `E033` и именем шаблона. Шаблон не меняет значение, а строит новое. Ниже - как переписать типичные места.

Было - падает с `E033`:

```jinja
{% set body = [] %}
{% for s in page.sections.values() %}
  {% if s.id not in ['short', 'faq'] %}{% set _ = body.append(s) %}{% endif %}
{% endfor %}
{% if page.sections.get('faq') %}{% set _ = body.append(page.sections['faq']) %}{% endif %}
{% set found = [] %}
{% for p in page.children %}
  {% if p.meta.extra.get('cluster') %}{% set _ = found.append(p) %}{% endif %}
{% endfor %}
{% set attrs = {'class': 'card'} %}
{% if page.meta.get('accent') %}{% set _ = attrs.update({'accent': page.meta.get('accent')}) %}{% endif %}
```

Стало - тот же результат без изменения данных:

```jinja
{% set faq = page.sections.get('faq') %}
{% set body = page.sections.values()|rejectattr('id', 'in', ['short', 'faq'])|list %}
{% set toc = body + ([faq] if faq else []) %}
{% set acc = namespace(found=[]) %}
{% for p in page.children %}
  {% if p.meta.extra.get('cluster') %}{% set acc.found = acc.found + [p] %}{% endif %}
{% endfor %}
{% set found = acc.found %}
{% set attrs = {'class': 'card'} %}
{% if page.meta.get('accent') %}{% set attrs = dict(attrs, accent=page.meta.get('accent')) %}{% endif %}
```

Приёмы:

- **Отбирать - фильтром.** `rejectattr`, `selectattr`, `select`, `reject`, `map(attribute='url')`. В конце добавьте `|list`, если результат нужен списком, а не для одного прохода.
- **Убрать повторы - `unique`** с атрибутом и обязательно с `case_sensitive=True`, иначе `/A/` и `/a/` склеятся в один адрес: `{% set links = (page.related.get('see_also', []) + more)|unique(case_sensitive=True, attribute='url')|list %}`.
- **Добавить элемент - сложением списков:** `body + [x]`, `body + ([faq] if faq else [])`.
- **Добавить ключ - новым словарём:** `dict(base, key=val)`. Ключ с дефисом так не передать - соберите словарь целиком: `{'class': 'card', 'data-x': x}`.
- **Копить в цикле - только через `namespace()`.** Обычный `{% set %}` внутри `for` живёт только до конца шага: `{% set found = found + [p] %}` в теле цикла не меняет `found` снаружи, и после цикла список снова пуст. Атрибут `namespace` (`acc.found`) цикл переживает.
- **Осторожно со `StrictUndefined`.** `selectattr('meta.extra.cluster', ...)` падает на первой же странице, где такого ключа нет. Для необязательного ключа - цикл с `namespace` и `.get('cluster')`, как в примере.
- **Ставьте теги на те же строки, где были старые.** Строка, где стоит только `{% %}`, ничего не выводит (`trim_blocks` и `lstrip_blocks`), поэтому замена тега на тег не меняет пробелы в HTML.

Найти такие места ещё до сборки помогает `check`: он разбирает шаблоны темы и называет каждый вызов, который даст `E033`, с файлом, строкой и рецептом замены - даже в шаблоне, который тема пока не использует ([`21` §12](../spec/21-engine.md#check-report)). Команда целиком - в разделе «Как проверить тему» ниже.

Проверка после правки - `build`: ни одного `E033`, а страницы такие же, как до правки.

## Строки интерфейса

Тексты, которые принадлежат теме, а не странице, - «Читать далее», заголовок блока вопросов, подписи кнопок - лежат в `theme/i18n/<язык>.yaml`, по файлу на язык:

```yaml
# theme/i18n/en.yaml
read_more: Read more
faq: Questions and answers
```

```yaml
# theme/i18n/ru.yaml
read_more: Читать далее
faq: Вопросы и ответы
```

В шаблоне строка выводится так: `{{ t.read_more }}`. Если строки для какого-то языка не хватает, сборка не падает: на странице останется имя ключа, а в отчёте появится предупреждение. Текст, зашитый прямо в шаблон, делает тему одноязычной - держите его в `i18n`.

## Картинки в теме

```jinja
{{ picture(page.meta.image, '16:9', alt=page.meta.image_alt) }}
```

Эта строка выводит готовый тег `<picture>`. Движок нарезает картинку под ширины и пропорции из `theme.yaml`: иллюстрации вписывает целиком, фотографии обрезает. Путь к картинке берётся из контента, а тема решает только пропорцию и место на странице.

**Нарезается только то, что попросил шаблон.** `ratios` в `theme.yaml` - пропорции, которые тема *может* попросить, а в сборку попадают только те, что шаблоны действительно вызвали через `picture()` или `media_url()`. Карточка просит 16:9 - значит, у её картинки в сборке будет только 16:9. Запасной файл в исходном формате (для браузеров без AVIF и WebP) - один на пропорцию, шириной `images.fallback_width` (по умолчанию 800). Нужна ширина больше - попросите её явно: `media_url(src, '16:9', 1200)` для og:image. → [`20` §7](../spec/20-data-contract.md#images)

## Обновление темы до строгого CSP <a id="strict-csp"></a>

Движок отдаёт страницы с правилом безопасности `script-src 'self'`: браузер выполняет только скрипты из файлов сайта, а скрипт, вписанный прямо в HTML (инлайн), не выполнит. Если ваша тема старой версии и в ней есть такой скрипт:

1. перенесите код в файл темы (`assets/site.js`);
2. данные (номера счётчиков и подобное) передавайте атрибутами `data-*` на теге `<script src="/assets/site.js">`, как в `base.html` стартовой темы;
3. запустите `check`: инлайн-скрипт в теме он показывает предупреждением.

## Как проверить тему

```bash
docker run --rm -v "$PWD:/site" -w /site --user "$(id -u):$(id -g)" ghcr.io/fmstm/heron:prod check .
docker run --rm -v "$PWD:/site" -w /site --user "$(id -u):$(id -g)" ghcr.io/fmstm/heron:prod check . --theme
docker run --rm -v "$PWD:/site" -w /site --user "$(id -u):$(id -g)" ghcr.io/fmstm/heron:prod build .
```

- `check` - отчёт без сборки: быстро показывает ошибки и предупреждения, в том числе по шаблонам;
- `check --theme` - ещё и демо темы: у каждого типа есть страница, каждый блок и вид раздела показан ([«Демо темы и справка»](#theme-demo));
- `build` - тема отрисовывает каждую страницу; ошибка шаблона называет страницу и шаблон;
- отчёт после сборки показывает секции, которых нет в `uses`, формы не того вида и недостающие строки `i18n`.
