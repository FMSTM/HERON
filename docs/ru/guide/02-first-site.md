# 02 · Первый сайт

В этом разделе мы с нуля сделаем небольшой сайт на двух языках: основной - английский, второй - русский. На каждом шаге разберём, что делает команда, что она напечатает и что появится в папке. Это займёт минут двадцать.

Нужен Docker - как его поставить, написано в [00 · Установка](00-install.md). Все команды ниже написаны целиком: копируйте их в терминал как есть.

> **Поставили движок без Docker?** Тогда в каждой команде всё, что стоит до имени образа (`ghcr.io/fmstm/heron:…`) включительно, замените словом `heron`. Например, `docker run … ghcr.io/fmstm/heron:prod build мой-сайт` превращается в `heron build мой-сайт`. Подробнее - [в разделе об установке](00-install.md#without-docker).

## Шаг 0. Папка для сайтов

Откройте терминал и создайте папку, где будут лежать сайты, например `sites` в домашней папке. Затем перейдите в неё:

```bash
mkdir -p ~/sites
cd ~/sites
```

Все команды ниже запускайте **из этой папки**. Docker показывает движку только текущую папку и то, что внутри неё, поэтому важно, где вы находитесь (подробнее - [в разделе об установке](00-install.md#docker-current-folder)).

## Шаг 1. Создать сайт

```bash
docker run --rm -it -v "$PWD:/site" -w /site --user "$(id -u):$(id -g)" ghcr.io/fmstm/heron:prod new мой-сайт
```

Движок создаст папку `мой-сайт` внутри текущей - получится `~/sites/мой-сайт` - и положит в неё всё, что нужно сайту. Имя папки может быть любым, на адрес сайта оно не влияет.

Что значат части команды - один раз, дальше они повторяются:

- `docker run --rm` - запустить движок и убрать за собой, когда команда закончится;
- `-it` - подключить терминал. Командам `new`, `page add` и `category add` - чтобы движок мог задавать вопросы, конфигуратору, студии и просмотру - чтобы их можно было остановить Ctrl+C;
- `-v "$PWD:/site" -w /site` - показать движку текущую папку и работать в ней;
- `--user "$(id -u):$(id -g)"` - создавать файлы от вашего имени. Без этого они достались бы системному пользователю root, и править их пришлось бы через `sudo`;
- `ghcr.io/fmstm/heron:prod` - сам движок, стабильная версия;
- `new мой-сайт` - команда движка и её параметры. Меняется только эта часть.

Надоест копировать длинную строку - задайте короткое имя `heron` на время работы, как описано [в разделе об установке](00-install.md#alias).

**Если папка для сайта уже есть** - например, вы создали пустой репозиторий на GitHub и склонировали его, - перейдите в неё и создайте сайт прямо там. Точка в конце означает «в текущей папке»:

```bash
cd ~/sites/my-repo
docker run --rm -it -v "$PWD:/site" -w /site --user "$(id -u):$(id -g)" ghcr.io/fmstm/heron:prod new .
```

`.git`, `.gitignore`, `README` и другие служебные файлы не мешают и не перезаписываются. Если в папке лежит что-то ещё, движок откажется и перечислит, какие файлы мешают: так он ничего не затрёт. В этом случае запускайте все следующие команды из этой папки (`~/sites/my-repo`) и вместо `мой-сайт` пишите `.`; в команде nginx из шага 6 путь станет `$PWD/dist`.

### Вопросы

`new` задаст несколько вопросов. В квадратных скобках - ответ по умолчанию: если он подходит, нажмите Enter.

```
Language you prefer to work in: hints, messages, comments in files
На каком языке вам удобнее работать: подсказки, сообщения, комментарии в файлах
  › (en, ru) [en] ru
Название сайта - как сайт называется для людей: в шапке, в <title>, в разметке
  › [мой-сайт] Workshop
Домен - без https:// и слешей, например example.com. Не знаете - Enter, останется заглушка
  › [workshop.example] workshop.example
Языки сайта - коды через запятую: en или en, ru. Каждый язык - папка content/<код>/
  › [en] en, ru
Основной язык - отдаётся из корня (/about/), остальные - с префиксом (/ru/about/)
  › [en] en
Итого: ...
Создать сайт? [Y/n]
```

Что спрашивают и на что это влияет:

- **язык работы** - на нём движок будет писать сообщения и комментарии в файлах. С языками самого сайта он не связан: можно работать по-русски над сайтом только на английском;
- **название** - как сайт называется для людей: в шапке и во вкладке браузера;
- **домен** - адрес, по которому сайт будет открываться, например `workshop.example`. Не знаете ещё - нажмите Enter и поменяйте потом;
- **языки сайта** - на каких языках будут страницы. Для каждого языка появится своя папка с текстами;
- **основной язык** - его страницы откроются по коротким адресам (`/about/`), страницы остальных языков - с приставкой (`/ru/about/`). Этот вопрос задаётся, только если языков больше одного.

В конце движок покажет сводку «Итого» и попросит подтвердить. Enter - и сайт создан.

### Что напечатает движок

```
Сайт создан: мой-сайт
Создано:
  + конфиг: site.yaml, .gitignore
  + контент en: главная, blocks.md, themes.md, docs.md, structure/_index.md, structure/one-intent.md, structure/categories.md, страница 404
  + контент ru: главная, blocks.md, themes.md, docs.md, structure/_index.md, structure/one-intent.md, structure/categories.md, страница 404
  + тема: 25 файлов - theme.yaml, шаблоны, модули, стили
  ...

Что дальше:
  1. Настройте сайт в конфигураторе:
      docker run --rm -it -p 127.0.0.1:8000:8000 -p 127.0.0.1:8001:8001 -v "$PWD:/site" -w /site --user "$(id -u):$(id -g)" ghcr.io/fmstm/heron:prod setup мой-сайт
    название, домен, кто вы, публикация. Или руками в мой-сайт/site.yaml.
  ...
```

В блоке «Что дальше» движок подсказывает следующие шаги - мы пройдём их по порядку ниже. В Docker каждая подсказка - готовая команда `docker run …` отдельной строкой: выделите строку целиком и вставьте в терминал. Если движок поставлен без Docker, подсказки короткие и стоят прямо в тексте - например, `heron setup мой-сайт`: их копируют без кавычек.

### Что появилось в папке

```
мой-сайт/
├── site.yaml          настройки сайта: домен, языки, меню, тема. Главный файл
├── content/
│   ├── en/            страницы на английском: index.md - главная, 404.md - «не найдено»
│   └── ru/            то же на русском
├── media/             картинки, видео, документы
├── theme/             оформление: шаблоны и стили. Пока - стартовая белая тема
├── data/  static/  plugins/    пока пустые, понадобятся позже
├── heron-readme.md    записка о том, что лежит в папке. Такая есть в каждой папке
└── AGENTS.md, CLAUDE.md, GEMINI.md, agents/   инструкции для AI-агента, если тексты будет писать он (об этом ниже)
```

Кроме главной, в `content/` лежат демонстрационные страницы:

- «Блоки» (`blocks.md`) - все виды блоков, которые умеет показывать тема;
- «Темы» (`themes.md`) - как сменить оформление;
- «Документация» (`docs.md`) - где читать дальше;
- «Структура» (папка `structure/`) - раздел со своей страницей `_index.md` и двумя страницами внутри: как разложить сайт по страницам и разделам.

Их удобно смотреть так: файл в редакторе слева, та же страница в браузере справа. Тексты демонстрационных страниц есть на русском, украинском и английском, остальные языки получают английские - с пометкой `translation: pending` (кроме основного языка): боевая сборка не выпустит английский текст под видом немецкого, пока его не переведут. Если у такого языка не переведена и главная, боевая сборка остановится (`E028`) и подскажет: перевести главную или убрать язык из `site.languages`. Это демо темы - образец, который продумал её автор: какие страницы нужны сайту, какие блоки на них. Замените тексты своими или, когда страницы станут не нужны, удалите файлы и уберите их из меню - `nav.main` в `site.yaml`. Как убрать демо и как вернуть его - [04 · Тема и дизайн](04-theme.md#demo-pages).

**Если тексты будет писать AI-агент.** Дайте ему ссылку на репозиторий сайта и задачу: «Прочитай `AGENTS.md` и напиши тексты страниц». В `AGENTS.md` описаны роли агента; тексты и SEO - роль «Контент и SEO». В папке `agents/` лежит документация движка той же версии и на том же языке, что выбрали вы; на сайт она не попадает. Если агенты не нужны, создавайте сайт с флагом `--no-agents` в конце команды `new` - движок запомнит это в `site.yaml`. Вышла новая версия движка - команда `init мой-сайт --agents` обновит инструкции, которые вы не правили. Подробнее - [`agents/README.md`](../README.md).

## Шаг 2. Посмотреть сайт в браузере

```bash
docker run --rm -it -p 127.0.0.1:8000:8000 -v "$PWD:/site" -w /site --user "$(id -u):$(id -g)" ghcr.io/fmstm/heron:prod serve мой-сайт
```

Здесь добавился `-p 127.0.0.1:8000:8000`: он пробрасывает порт 8000 из контейнера, чтобы страницу можно было открыть в браузере. `127.0.0.1` значит, что страница видна только на вашем компьютере, а не во всей сети.

Движок соберёт сайт и напечатает:

```
открыто: http://localhost:8000/  (Ctrl+C - выход)
HERON работает в контейнере: откройте адрес на своём компьютере. ...
```

Откройте <http://localhost:8000> в браузере. Это уже рабочий сайт: главная, меню, переключатель языков, демонстрационные страницы. А по адресу <http://localhost:8000/_heron/theme/> - справка темы: каждый блок, который она умеет, с подсказкой, живым примером и его markdown рядом. Справку видно только в просмотре: на сайт она не попадает.

Пока просмотр запущен, движок следит за файлами: сохранили правку - страница пересобралась, обновите вкладку браузера. Поэтому удобно держать просмотр запущенным всё время работы, а остальные команды выполнять **в соседней вкладке терминала** (не забудьте и там перейти в `~/sites`). Остановить просмотр - Ctrl+C.

## Шаг 3. Настроить сайт

Все настройки сайта хранятся в одном файле - `мой-сайт/site.yaml`. Заполнить его можно двумя способами.

### Способ 1: конфигуратор в браузере

Если просмотр запущен (в любой вкладке) - сначала остановите его Ctrl+C: конфигуратору нужен тот же порт 8000. Ещё один порт, 8001, конфигуратор и студия берут для просмотра страниц и справки темы - поэтому в команде два `-p`. Второй порт работает сам: студия находит его без вашей помощи. Если 8001 занят другой программой, движок так и скажет - тогда добавьте `--preview-port` с другим номером и тот же номер во второй `-p`. Затем:

```bash
docker run --rm -it -p 127.0.0.1:8000:8000 -p 127.0.0.1:8001:8001 -v "$PWD:/site" -w /site --user "$(id -u):$(id -g)" ghcr.io/fmstm/heron:prod setup мой-сайт
```

Движок напечатает адрес вида:

```
Конфигуратор открыт: http://localhost:8000/#eeRjEhS4PDDywTrtEWihlUwHRyY3mvzx  - откройте адрес целиком, с ключом после «#».
```

Откройте этот адрес в браузере **целиком, вместе с длинным ключом после `#`**. Ключ - пароль на этот запуск конфигуратора: без него конфигуратор не покажет настройки, и никто, кроме вас, не сможет их поменять.

В конфигураторе - название и домены, языки, сведения о вас или вашей организации (сфера, адрес, контакты - это попадёт в разметку для поисковиков), подключение аналитики, способ публикации, тема. Интерфейс на двух языках, переключается кнопками EN и RU.

Кнопка «Сохранить» записывает ответы в `site.yaml`, а если отметите в конфигураторе - ещё и помощников для публикации: скрипты `.heron/scripts/build.sh` и `.heron/scripts/publish.sh`, `.gitignore` и сценарий автосборки для GitHub. Ваши комментарии и настройки, которых нет в конфигураторе, остаются на месте, а прежняя версия файла сохраняется в `мой-сайт/.heron-cache/setup/`. Конфигуратор можно запускать сколько угодно раз - он покажет то, что уже записано. Закончили - Ctrl+C в терминале.

AI-агенту и CI браузер не нужен: те же поля заполняются файлом. Команда `setup мой-сайт --dump > answers.yaml` выгружает текущие ответы, после правки `setup мой-сайт --answers answers.yaml` их записывает. Подробнее - [`21` §10](../spec/21-engine.md#heron-setup).

### Способ 2: вручную в `site.yaml`

`site.yaml` - обычный текстовый файл, у каждой настройки в нём есть комментарий. Ответы на вопросы `new` там уже записаны. Например, добавим название сайта по-русски, окончание заголовка вкладки и меню:

```yaml
site:
  domain: example.com
  name: Workshop
  name_ru: Мастерская         # название на русских страницах
  theme: main
  default_lang: en            # основной язык: адреса вида /about/
  languages: [en, ru]         # второй язык: адреса вида /ru/about/
seo:
  title_suffix: " - Workshop"          # добавляется к заголовку каждой страницы
  title_suffix_ru: " - Мастерская"
nav:
  main: ["/", about]          # меню: главная и страница about
```

Обратите внимание на меню: в нём не адреса, а **ключи страниц**. Ключ - это имя файла без `.md`: `about` - это `content/en/about.md` на английском и `content/ru/about.md` на русском. Нужный адрес для каждого языка движок подставит сам.

Все настройки с пояснениями - [`20` §5](../spec/20-data-contract.md#site-yaml), полный образец - [`templates/site.yaml`](../templates/site.yaml).

### Если поменяли языки

Добавили язык - например, `de` в `languages` - выполните:

```bash
docker run --rm -v "$PWD:/site" -w /site --user "$(id -u):$(id -g)" ghcr.io/fmstm/heron:prod init мой-сайт
```

`init` достроит недостающее: создаст `content/de/` со стартовыми страницами и надписи темы на немецком, обновит языки в `AGENTS.md`. Ваши тексты, тему и настройки он не трогает (перезаписать заготовками - флаг `--force`). Если языки не менялись, этот шаг не нужен.

А если `site.yaml` в папке нет - например, вы принесли готовые тексты из другого места, - `init` задаст те же вопросы, что и `new` (добавьте в команду `-it`, как у `new`), и предложит языки по папкам, которые уже лежат в `content/`.

## Шаг 4. Написать главную

Откройте в редакторе `мой-сайт/content/en/index.md`. Файл состоит из двух частей.

**Вверху - SEO-блок** между строками `---`. Его читают поисковики и браузер:

- `title` - заголовок в выдаче поисковика и во вкладке браузера;
- `h1` - главный заголовок на самой странице, для того, кто её уже открыл;
- `description` - короткое описание, которое поисковик показывает под заголовком.

Замените их своими. Комментарии в блоке не удаляйте: они подсказывают, что куда писать, вам и тому, кто будет править файл после вас.

**Ниже - текст страницы.** Сначала вступление - обычные абзацы. Потом секции: каждая начинается с заголовка `##`, а после него в фигурных скобках - **якорь**, короткое латинское имя секции:

```markdown
We have been repairing roofs since 2010.

We come out to measure the same day you call.

## What we do {#about}

- **Roof repair.** Patching and re-covering.
- **Gutters.** Installation and cleaning.
```

По якорю тема понимает, что это за секция и где её показать. Поэтому в русской главной (`content/ru/index.md`) якорь тот же, а заголовок и текст русские: `## Что мы делаем {#about}`.

Сохраните файлы. Если просмотр запущен, обновите вкладку браузера и посмотрите результат. Какие секции и как показывает главная, решает тема - подробнее в [04 · Тема и дизайн](04-theme.md).

## Шаг 5. Добавить страницу

Добавим страницу «О нас» с ключом `about`:

```bash
docker run --rm -it -v "$PWD:/site" -w /site --user "$(id -u):$(id -g)" ghcr.io/fmstm/heron:prod page add about мой-сайт
```

Как читать конец команды: `page add` - «создай страницу, а если она уже есть - открой на правку», `about` - её **ключ** (из него получится имя файла и адрес), `мой-сайт` - папка сайта. `-it` нужен, потому что движок задаёт вопросы: в какой категории лежит страница, заголовок для поиска, заголовок на самой странице, описание и остальные поля. У каждого вопроса в скобках стоит значение, которое останется, если просто нажать Enter, рядом - подсказка в одну строку, а `?` покажет подробную справку. Ответ с ошибкой (например, пустое обязательное поле) движок отметит сразу и спросит ещё раз, а замечание (например, `title` длиннее 60 знаков) покажет и запишет ответ - его можно поправить потом. Сначала он спросит всё на основном языке, потом для каждого другого языка - перевод тех же текстов: введите перевод или нажмите Enter, чтобы пропустить поле. Как отвечать на вопросы, с примером, - [03 · Страницы и контент](03-content.md#questions).

В конце движок покажет итог и спросит «Записать?». Страница появится сразу на всех языках: `мой-сайт/content/en/about.md` и `мой-сайт/content/ru/about.md` - с готовым SEO-блоком и заготовками секций. Если перевод вы пропустили, в русском файле останется английский текст и строка `translation: pending`: черновая сборка и просмотр покажут такую страницу с жёлтой плашкой «перевод не готов», а боевая сборка не опубликует её на русском, пока вы не переведёте текст и не удалите эту строку.

Та же команда второй раз откроет страницу на правку, ничего не создавая. Все страницы, их языки и непереведённое (отмечено `!`) показывает `page list`:

```bash
docker run --rm -v "$PWD:/site" -w /site --user "$(id -u):$(id -g)" ghcr.io/fmstm/heron:prod page list мой-сайт
```

Имена файлов во всех языках одинаковые - так движок понимает, что это переводы одной страницы. А адреса могут отличаться: чтобы русская страница открывалась по `/ru/o-nas/`, допишите в её SEO-блок `slug: o-nas` (`page add` спросит и это поле).

```
content/en/about.md   →  /about/
content/ru/about.md   →  /ru/o-nas/      (в SEO-блоке: slug: o-nas)
```

Новая страница сама попадёт в карту сайта для поисковиков. В меню она появится, если её ключ `about` есть в `nav.main` (шаг 3), и на русских страницах этот пункт сам поведёт на `/ru/o-nas/`.

Можно обойтись и без команды: скопируйте любой файл страницы под новым именем и поправьте. Результат тот же.

А можно - мышью, в студии в браузере: дерево страниц слева, поля с подсказками справа, языки вкладками. Остановите просмотр (Ctrl+C) - студии нужен тот же порт - и запустите:

```bash
docker run --rm -it -p 127.0.0.1:8000:8000 -p 127.0.0.1:8001:8001 -v "$PWD:/site" -w /site --user "$(id -u):$(id -g)" ghcr.io/fmstm/heron:prod studio мой-сайт
```

Откройте адрес, который напечатает движок, целиком - с ключом после `#`, как у конфигуратора. Что в студии - [03 · Страницы и контент](03-content.md#studio).

## Шаг 6. Проверить и собрать

```bash
docker run --rm -v "$PWD:/site" -w /site --user "$(id -u):$(id -g)" ghcr.io/fmstm/heron:prod build мой-сайт
```

Движок соберёт готовый сайт в папку `мой-сайт/dist/` и напечатает отчёт: сколько страниц на каждом языке и есть ли замечания. Например, если новые страницы из шага 5 ещё не правили:

```
Предупреждений - 2:
  прочее - 2:
    en/about.md: title и h1 совпадают: title пишется под выдачу, h1 под того, кто уже открыл
    ru/about.md: title и h1 совпадают: title пишется под выдачу, h1 под того, кто уже открыл
```

Сообщения бывают двух видов:

- **предупреждение** - сайт собран, но что-то стоит поправить. Здесь движок подсказывает, что заголовок для поисковика и заголовок на странице одинаковые, а лучше сделать их разными;
- **ошибка** - сайт не собран. Движок пишет код ошибки (например, `E006`), файл и, если может, номер строки. Что значат коды - в [`21-engine.md`](../spec/21-engine.md).

Чтобы только проверить, ничего не собирая, замените в команде `build` на `check`: отчёт тот же, а работает быстрее.

### Посмотреть собранный сайт

Просмотр из шага 2 собирает сайт во временную папку. Чтобы посмотреть именно то, что лежит в `dist/`, запустите его простым веб-сервером nginx:

```bash
docker run --rm -p 127.0.0.1:8080:8080 -v "$PWD/мой-сайт/dist:/usr/share/nginx/html:ro" nginxinc/nginx-unprivileged:1.30.6-alpine
```

и откройте <http://localhost:8080>. Без Docker то же самое делает `python3 -m http.server 8080 -d мой-сайт/dist`.

Это сервер без настроек сайта: своя страница «не найдено» и перенаправления со старых адресов здесь не работают. Как проверить сайт целиком - в [06 · Сборка и выкладка](06-deploy.md).

## Шаг 7. Боевая сборка

До сих пор все сборки были черновыми (dev): сайт закрыт от поисковиков, счётчики аналитики не подключаются. Для публикации нужна боевая сборка (prod):

```bash
docker run --rm -v "$PWD:/site" -w /site --user "$(id -u):$(id -g)" ghcr.io/fmstm/heron:prod build мой-сайт --env prod --strict
```

- `--env prod` - боевой режим: сайт открыт для поисковиков, подключены счётчики из настроек;
- `--strict` - строгий режим: любое предупреждение считается ошибкой, и сборка останавливается. Так на живой сайт не попадёт битая ссылка или картинка без описания.

Если строгая сборка остановилась, движок перечислит, что поправить. Папка `dist/` при этом остаётся от прошлой удачной сборки - сломанный сайт в неё не попадёт. Например, страница из шага 5 не соберётся, пока у неё одинаковые `title` и `h1`.

Готовую папку `dist/` можно положить на любой хостинг. Как упаковать её в Docker-образ с nginx и выложить на свой сервер - в [06 · Сборка и выкладка](06-deploy.md).
