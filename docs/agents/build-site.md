# Сценарий А: собрать сайт по структуре контента

**На входе:** документ со структурой сайта (дерево страниц, типы, секции по типам, языки; обычно по форме [`templates/structure.md`](templates/structure.md)), иногда — тексты и картинки.
**На выходе:** папка сайта, которая собирается `build --env prod --strict` без ошибок, и отчёт: что сделано, список долгов контента, вопросы.

Команды ниже — через образ. Без докера то же самое делает `heron <команда>` из pip-пакета.

```bash
H="docker run --rm -v $PWD:/site -w /site --user $(id -u):$(id -g) ghcr.io/fmstm/heron:prod"
```

## 1. Создать папку

```bash
$H new мой-сайт           # site.yaml, .gitignore, скелет темы, пояснительные записки
```

Если папка с контентом уже есть — не `new`, а `$H init мой-сайт`: он дописывает недостающее и ничего не перезаписывает.

## 2. Заполнить `site.yaml`

Возьми [`templates/site.yaml`](templates/site.yaml) как образец всех ключей. Минимум:

```yaml
heron: ">=0.1,<0.2"
site:
  domain: example.com
  theme: main
  default_lang: uk
  languages: [uk, ru]
  name: Название
  name_ru: Название по-русски      # если отличается
seo:
  title_suffix: " — Название"
  title_suffix_ru: " — Название"
nav:
  main: ["/", about, services, contacts]   # ключи страниц
```

Потом достроить папки под языки:

```bash
$H init мой-сайт          # появятся content/<lang>/ и theme/i18n/<lang>.yaml
```

Чего не делать: не писать домен, телефон, счётчики «примерные» — пусто лучше выдуманного. Не добавлять в папку Dockerfile, compose, `.env`.

## 3. Тема: `theme.yaml`

По структуре из документа заполни `types` — по типу на каждую раскладку страниц. Образец — [`templates/theme.yaml`](templates/theme.yaml).

```yaml
types:
  home:     {uses: [intro, "why:list", "how:steps", "faq:faq"], jsonld: [WebSite]}
  category: {uses: [intro]}
  service:  {uses: [intro, "includes:list", "when:alert-list", "how:steps", "documents:checklist", "faq:faq"], jsonld: [Service]}
  article:  {uses: [intro, "*"], jsonld: [Article]}
  page:     {uses: [intro, "*"]}
  "404":    {uses: [intro]}
links:
  - {field: related, type: service, back: related_from}
```

- `uses` перечисляет **все** секции типа, включая необязательные; после двоеточия — ожидаемая форма из таблицы `20` §4.4. `"*"` — тип принимает любые секции;
- на каждый тип — шаблон `theme/templates/<тип>.html`; на каждую форму, которую рисуешь, — модуль `theme/modules/<форма>.html`. Заготовка содержит `home`, `page`, `404` и модули `prose`, `list`, `steps`, `faq`, `facts`, `cards`, `breadcrumbs` — остальное дописать;
- в шаблоне: `mod.<модуль>('<якорь>')` рисует секцию или ничего, если её нет; `page_of('<ключ>')` — страница по ключу; `data.<файл>` — справочники. Полный список переменных — `21` §7.

## 4. Контент

На каждую страницу структуры — файл. Имя файла = ключ, **одинаковое во всех языках**.

```
content/uk/index.md                     главная, тип home
content/uk/404.md                       страница 404, тип 404
content/uk/about.md                     type: about, если у неё своя раскладка
content/uk/services/_index.md           раздел: children_type: service
content/uk/services/design.md
content/ru/services/_index.md           slug: katalog — если русский адрес другой
content/ru/services/design.md       slug: oformlenie
```

Фронтматтер — по [`templates/page.md`](templates/page.md): восемь групп, порядок и комментарии сохраняются, пустые необязательные поля остаются закомментированными. Обязательны `title`, `h1`, `description`.

Тело — вступление (не больше двух абзацев) и секции `## Заголовок {#якорь}` с якорями из `uses` типа. Форма секции задаётся разметкой (таблица `20` §4.4):

```markdown
Вступление: кому и с чем помогаем.

Второй абзац — обещание: чем заканчивается работа.

## Что входит {#includes}

- **Анализ документов.** Смотрим договор и переписку.
- **Позиция.** Пишем, что делать дальше.

## Как мы работаем {#how}

1. **Заявка.** Звоните или пишете.
2. **Встреча.** Обсуждаем дело.

## Частые вопросы {#faq}

### Сколько это длится?

Обычно две-три недели.
```

- ссылки на свои страницы — ключом, без языкового префикса: `[дизайн](/services/design/)`; на главную — `(/)`;
- старые адреса — `redirect_from` в файле той страницы, куда они ведут, в любом виде: кириллицей или `%D0%…`;
- адреса, которых больше нет, — `gone` в `site.yaml`, не в странице;
- нет материала для секции — **секцию не создавать**. Тема её не нарисует, а сводка долгов покажет, чего не хватает.

## 5. Картинки и данные

- картинки, видео, PDF — в `media/`, ссылки от корня сайта: `media/services/design.png`; у картинки обязателен `alt` (`image_alt`);
- иллюстрации — PNG/WebP с прозрачным фоном, любой пропорции: движок впишет; фото — JPEG, движок обрежет;
- сквозные данные (отзывы, цифры доверия, команда) — yaml в `data/`, тема берёт их как `data.<имя файла>`.

## 6. Цикл проверки

```bash
$H check мой-сайт                     # отчёт без сборки
$H build мой-сайт                     # дев-сборка в мой-сайт/dist
$H build мой-сайт --env prod --strict # как прод: предупреждения — ошибки
```

Читай отчёт целиком. Ошибки (`E0xx`) останавливают сборку — исправить. Предупреждения сгруппированы: `картинки`, `связи`, `ссылки`, `меню`, `переводы`, `языки`, `контент`, `прочее`; полный список — `.heron-cache/warnings.txt` рядом со сборкой. Сводка «Не заполнено» — долги контента, их — в отчёт заказчику.

Частые ошибки:

| Код | Что значит | Что делать |
|---|---|---|
| `E002` | нет `title`/`h1`/`description` или поле не того типа | дописать; даты — `ГГГГ-ММ-ДД` |
| `E004` | два файла дают один адрес | разные `slug` |
| `E005` | имя файла или `slug` не латиница-цифры-дефис | переименовать |
| `E006` | связь на страницу, которой нет | имя файла без расширения, не адрес |
| `E007` | файла из `media/` нет на диске | путь от корня сайта |
| `E008` | у типа нет шаблона | `theme/templates/<тип>.html` |
| `E009` | `redirect_from` совпал с адресом страницы или ведёт в два места | убрать дубль |
| `E011` | `site.yaml` не прошёл проверку | смотреть сообщение: опечатка в ключе ядра |
| `E020` | разметка: нет объявленного типа, пустой адрес в сквозном узле, цены | `schema` в `site.yaml`; цены — `seo.allow_prices` |
| `E021` | прод, а основной язык пуст | заполнить или сменить `default_lang` |
| `E022` | `gone` закрывает страницу или пересекается с `redirect_from` | выбрать одно |

Полный список — `21` §11.

## 7. Что проверить в собранном сайте

- `dist/index.html` и главные страницы каждого языка открываются, в `<head>` правильные `<title>` с суффиксом языка, `canonical`, hreflang (на многоязычном сайте);
- `dist/sitemap.xml` перечисляет все индексируемые страницы (на многоязычном — через `sitemap-<lang>.xml`); 404 и `noindex` там нет;
- `dist/404.html` и `dist/<lang>/404/index.html` на месте;
- `dist/llms.txt` — описание и перечень (или оглавление языков);
- `dist/redirects.map` и `dist/gone.map` — то, что ожидалось;
- в разметке (`<script type="application/ld+json">`) — нужные типы.

Ответы сервера (301, 410, 404 своего языка) проверяются на образе:

```bash
./scripts/site.sh <сайт> smoke prod      # из клона репозитория движка
```

## 8. Отчёт

Что сделано, какие страницы созданы, какие секции не заполнены (сводка долгов), какие факты не подтверждены (вопросы заказчику), какие предупреждения оставлены и почему, и — если были — расхождения документации с поведением движка.
