# Роль: Сборщик

Собрать сайт по структуре контента, проверить его и выложить. Если тема и страницы ещё не готовы, сборщик ведёт работу дизайнера ([`designer.md`](designer.md)) и контента ([`content.md`](content.md)) сам, по их чек-листам. Общие правила - [`README.md`](../README.md).

**На входе:** документ со структурой сайта (по форме [`templates/structure.md`](../templates/structure.md)), иногда - тексты и картинки.
**На выходе:** папка сайта, которая собирается `build --env prod --strict` без ошибок; при необходимости - образ; отчёт.

Команды записаны как `heron <команда>` - так они работают, если движок поставлен пакетом (`pipx install git+https://github.com/FMSTM/HERON.git@<канал>`). Через Docker то же самое - полная команда без `-it`, у агента нет терминала:

```bash
docker run --rm -v "$PWD:/site" -w /site --user "$(id -u):$(id -g)" ghcr.io/fmstm/heron:prod check мой-сайт
```

Путь к сайту - **относительно текущей папки**: контейнер видит только её. `.` - если ты в папке сайта.

Документация этой версии движка - `heron docs` (оглавление), `heron docs <тема>`, `heron docs --search <текст>`.

## 1. Создать папку

У агента нет терминала, поэтому `new` вопросов не задаёт - всё флагами:

```bash
heron new мой-сайт --notes ru --name "Название" --domain example.com --lang en,ru -y
```

- `--lang` - языки через запятую, первый - основной; `--domain` без схемы. Не знаешь домена - не передавай: останется заглушка `<имя>.example`, и это строка в отчёте;
- `--notes ru|en` - язык справки, сообщений и комментариев во всех файлах; по умолчанию `en`, запоминается в `build.notes`;
- папка под git (`.git`, `.gitignore`, `README`) годится: `heron new . …`;
- результат - `site.yaml`, тема, на каждом языке главная, 404 и демонстрационные страницы `blocks.md`, `themes.md`, `docs.md`, картинки `media/cover.png` и `media/demo/`, записки по папкам. Стартовый сайт собирается `--env prod --strict` без предупреждений. Демонстрационных страниц нет в структуре сайта: их судьба - строка в отчёте и вопрос человеку.

Папка с контентом уже есть - не `new`, а `heron init мой-сайт`: дописывает недостающее и ничего не перезаписывает.

## 2. Заполнить `site.yaml`

Образец всех ключей - [`templates/site.yaml`](../templates/site.yaml). Минимум:

```yaml
heron: ">=0.3,<0.4"
site:
  domain: example.com
  theme: main
  default_lang: en                 # из корня: /about/
  languages: [en, ru]              # русский - под /ru/
  name: Daybreak
  name_ru: Рассвет                 # если отличается
seo:
  title_suffix: " - Daybreak"
  title_suffix_ru: " - Рассвет"
nav:
  main: ["/", about, services, contacts]   # ключи страниц
```

Затем достроить папки под языки:

```bash
heron init мой-сайт          # content/<язык>/index.md и 404.md, theme/i18n/<язык>.yaml
```

Чего не делать: не писать домен, телефон, счётчики «примерные» - пусто лучше выдуманного. Не класть в папку Dockerfile, compose, `.env`.

## 3. Тема

`types` и `links` в `theme/theme.yaml` - из структуры; шаблон на каждый тип, модуль на каждую форму. Как - [`designer.md`](designer.md).

## 4. Контент

Файл на каждую страницу структуры; имя файла = ключ, одинаковое во всех языках. Новая страница - `heron page <тип> <имя> мой-сайт`. Как писать SEO-блок и секции - [`content.md`](content.md).

## 5. Цикл проверки

```bash
heron check мой-сайт                     # отчёт без сборки
heron build мой-сайт                     # дев-сборка в мой-сайт/dist
heron build мой-сайт --env prod --strict # как прод: предупреждения - ошибки
```

Читай отчёт целиком. Ошибки (`E0xx`) останавливают сборку - исправить. Предупреждения сгруппированы: `картинки`, `связи`, `ссылки`, `меню`, `переводы`, `языки`, `контент`, `даты`, `редиректы`, `прочее`, `нет перевода`; полный список - `.heron-cache/warnings.txt` рядом со сборкой. Сводка «Не заполнено» - долги контента, их - в отчёт.

Частые ошибки:

| Код | Что значит | Что делать |
|---|---|---|
| `E002` | нет `title`/`h1`/`description` или поле не того типа | дописать; даты - `ГГГГ-ММ-ДД` |
| `E004` | два файла дают один адрес | разные `slug` |
| `E005` | имя файла или `slug` не латиница-цифры-дефис | переименовать |
| `E006` | связь на страницу, которой нет | имя файла без расширения, не адрес |
| `E007` | файла из `media/` нет на диске | путь от корня сайта |
| `E008` | у типа нет шаблона или тема не знает тип | запись в `types` темы и `theme/templates/<тип>.html` |
| `E009` | `redirect_from` совпал с адресом страницы или ведёт в два места | убрать дубль |
| `E011` | `site.yaml` не прошёл проверку или тема требует пустой ключ | смотреть сообщение |
| `E012` | движок не из диапазона `heron:` в `site.yaml` | другой тег образа или диапазон |
| `E020` | разметка: нет объявленного типа, пустой адрес в сквозном узле, цены | `schema` в `site.yaml`; цены - `seo.allow_prices` |
| `E021` | прод, а основной язык пуст | заполнить или сменить `default_lang` |
| `E022` | `gone` закрывает страницу или пересекается с `redirect_from` | выбрать одно |

Полный список - `21` §11 ([`spec/21-engine.md`](../spec/21-engine.md)).

## 6. Что проверить в собранном сайте

- главные страницы каждого языка открываются; в `<head>` - `<title>` с суффиксом, `canonical`, hreflang (на многоязычном сайте);
- `dist/sitemap.xml` перечисляет все индексируемые страницы (на многоязычном - через `sitemap-<язык>.xml`); 404 и `noindex` там нет;
- `dist/404.html` и `dist/<язык>/404/index.html` на месте;
- `dist/llms.txt` - описание и перечень (или оглавление языков);
- `dist/redirects.map` и `dist/gone.map` (второй - только при непустом `gone`) - то, что ожидалось по таблице переноса;
- в разметке (`<script type="application/ld+json">`) - нужные типы; отчёт считает страницы по типам.

## 7. Выкладка

Папка `dist/` - на любой хостинг статики, с `.heron-nginx.conf` для своего nginx. Образ и проверка ответов сервера - из клона репозитория движка. Нужны настройки `env/.env.<сайт>.<окружение>`: их заводит `./scripts/site.sh <сайт> new <путь>`, для существующей папки - `cp env/.env.example env/.env.<сайт>.prod`.

```bash
./scripts/site.sh <сайт> build prod
./scripts/site.sh <сайт> image prod
./scripts/site.sh <сайт> smoke prod      # 200, 404, каждый 301 и каждый 410
./scripts/site.sh <сайт> push prod
```

Сайт в своём репозитории без клона HERON - переиспользуемый workflow `FMSTM/HERON/.github/workflows/site-image.yml`: собирает, упаковывает, проверяет и отправляет образ, свой Dockerfile не нужен.

Подробно - гайд [06 · Сборка и выкладка](../guide/06-deploy.md).

## 8. Отчёт

`agents/work/report.md` по форме [`templates/report.md`](../templates/report.md): что сделано; какие страницы созданы; какие секции не заполнены (сводка долгов); какие факты не подтверждены (вопросы - `agents/work/questions.md`); какие предупреждения оставлены и почему; расхождения документации с поведением движка, если были; команды проверки и их коды выхода.

**Граница публикации.** Выкладка (раздел 7) - команды человека: `.heron/scripts/publish.sh`, `docker push`, `site.sh push`, `git push`, merge ты не запускаешь. Твой результат - ветка с правками, зелёные `check --strict --json` и `build --env prod --strict`, отчёт и вопросы. Код в `plugins/` без явной задачи от человека не пишешь: плагин исполняется при сборке.

## Чек-лист

- [ ] `site.yaml`: `heron:`, домен, языки, название, меню; нет выдуманных фактов
- [ ] у каждого типа из структуры - шаблон; у каждой страницы - файл
- [ ] `build --env prod --strict` без ошибок
- [ ] карты 301/410 совпадают с таблицей переноса; `smoke prod` зелёный
- [ ] отчёт: долги, вопросы, оставленные предупреждения
