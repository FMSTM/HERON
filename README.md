# HERON

Файловый движок сайтов. На вход — папка с контентом в markdown, темой и одним конфигом. На выходе — статический сайт в `dist/` или образ nginx с этим сайтом внутри.

**Статус: в разработке.** Каркас и контракты на месте, сборка ещё не работает. Команды отвечают номером задачи, которая их реализует.

## Установка

```bash
docker pull ghcr.io/OWNER/heron:dev
```

или для локальной разработки:

```bash
uv pip install -e .
```

## Команды

```
heron new <имя>                        создать папку сайта с нуля
heron init                             дополнить существующую папку недостающим
heron check [--strict]                 отчёт без сборки
heron serve [--port 8000]              локальный просмотр с пересборкой
heron build [--drafts] [--strict]      собрать в dist/
heron build --image <tag>              собрать и упаковать в образ nginx
heron page <тип> <слаг>                заготовка страницы
```

## Безопасный запуск

Сборщику статики не нужно ничего — ни сети, ни прав, ни секретов:

```bash
docker run --rm \
  --network=none \
  --read-only --tmpfs /tmp \
  --cap-drop=ALL --security-opt=no-new-privileges \
  --user "$(id -u):$(id -g)" \
  -v "$PWD:/site" \
  ghcr.io/OWNER/heron:dev build --strict
```

Docker-сокет внутрь контейнера не пробрасывается никогда. `build --image` выполняется на хосте.

## Ветки

`dev` — основная разработка, каждая фича приходит своей веткой. `stage` — обкатка. `prod` — то, на чём стоят сайты; релиз режется тегом `vX.Y.Z`.

Образы: ветка даёт `:dev`, `:stage`, `:prod`; тег `v0.2.0` даёт `:0.2.0`, `:0.2` и `:latest`.

## Граница

Ядро не знает ни про один конкретный сайт: ни имён, ни доменов, ни телефонов. Проверяется хуком `scripts/check-boundaries.sh` на каждый коммит и в CI по всем файлам репозитория.
