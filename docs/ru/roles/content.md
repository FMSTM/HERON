# Роль: Контент и SEO

Писать и переносить страницы, заполнять SEO-блок, вести переводы и старые адреса. Общие правила - [`README.md`](../README.md); как устроена страница по-человечески - гайд [03 · Страницы и контент](../guide/03-content.md), что генерируется само - [05 · SEO](../guide/05-seo.md).

**На входе:** структура сайта (ключи, типы, секции по типам, языки) и тексты или факты заказчика. Для существующего сайта - сама папка.
**На выходе:** файлы `content/<язык>/…md`, картинки в `media/`, справочники в `data/`, `redirect_from` у страниц, список долгов контента и вопросов.

**Границы.** Пишешь только в `content/`, `media/`, `data/`. `theme/`, структура `site.yaml` (языки, тема, меню), `.github/`, скрипты - не твои. Факты, которых нет в источнике, - в `agents/work/questions.md`, поле пустое. Отчёт - `agents/work/report.md` по форме [`templates/report.md`](../templates/report.md). Готово, когда `heron check . --strict --json` отвечает кодом 0.

## 1. Создать файл

```bash
heron describe --json мой-сайт                                    # поля и подсказки темы
heron page add roof --type service --category services мой-сайт --dump > roof.yaml
heron page add roof --type service --category services мой-сайт --answers roof.yaml
```

Одна команда - страница на **всех** языках `site.yaml`: `content/<язык>/services/roof.md`. Есть - правка, нет - создание. `--dump` печатает все поля по языкам (у новой страницы - заготовку), ты заполняешь их и отдаёшь через `--answers`; путь поля - как в `heron describe --json` (`title`, `sections.faq.items`). Язык, который пока не переводишь, - `de: pending` или без полей: файл получит текст основного языка и `translation: pending`, боевая сборка его не опубликует (`20` §4.2). `heron page list мой-сайт --json` показывает, где перевод не готов. Раздел - `heron category add services мой-сайт`, перенос страницы - `--category` другого раздела (301 со старых адресов ставится сам). Ошибки ответов - `E039`, старая форма `heron page <тип> <имя>` - `E038`.

Тип должен быть объявлен в `types` темы. В стартовой теме есть только `home`, `page`, `404`; другой тип даёт `E008`, его сначала добавляет дизайнер.

`heron page add` кладёт полный SEO-блок и заготовки **всех** секций, которые тема объявила у типа (`types.<тип>.uses`). Можно и скопировать готовый файл - результат тот же. Образец заполненной страницы - [`templates/page.md`](../templates/page.md).

Имя файла - ключ страницы: латиница, цифры, дефис; **одинаковое во всех языках**. Другой адрес у перевода - поле `slug`.

## 2. SEO-блок

Восемь групп, порядок и комментарии сохраняются; пустые необязательные поля остаются закомментированными.

| Группа | Что заполнять |
|---|---|
| 1. Основное | `title` (до 60 знаков, для выдачи), `h1` (для того, кто открыл; не копия `title`), `description` (до 155 знаков: что человек получит). `slug` - если адрес не равен имени файла. `canonical` и `robots` не трогать |
| 2. Ключевые запросы | основной и дополнительные. Движок не читает; правило - один интент, одна страница |
| 3-4. Open Graph, Twitter | только если отличается от `title`/`description`/картинки по умолчанию |
| 5. Schema.org | уточнения разметки этой страницы; данные организации - не здесь, а в `site.yaml` |
| 6. Карточка | `image` + `image_alt` для каталога; `order`; `type`, если не задан разделом |
| 7. Служебное | `date`, `updated`, `published`, `noindex` |
| 8. Связи | поля связей темы (имена файлов без `.md`) и `redirect_from` |

Все поля и значения по умолчанию - `20` §4.2.

## 3. Текст

- **вступление** - до первого `##`, не больше двух абзацев: подводка и обещание;
- **секции** - `## Заголовок {#якорь}`, якоря - из `uses` типа. Опечатка в якоре - строка «тема не использует» в отчёте;
- **форма** секции - разметкой: список, `1.` шаги, `### Вопрос?` FAQ, `ключ | значение` факты, таблица, `>` совет; классы `.alert`, `.timeline`, `.gallery` в якоре. Таблица - `20` §4.4;
- **нет материала - нет секции.** Заготовку из `heron page add` удалить, а не заполнять общими словами.

## 4. Ссылки и связи

- на свои страницы - ключом от корня без языкового префикса: `[кровля](/services/roof/)`, главная - `(/)`. Движок подставит адрес нужного языка;
- «смотрите также», «по теме» - поля связей из `theme.yaml` (`related: [gutter]`), не ручные списки ссылок;
- телефон, адрес, часы, соцсети - не в тексте, а в `contact`/`organization` в `site.yaml`.

## 5. Картинки

Файлы - в `media/`, путь от корня сайта: `media/services/roof.png`. Иллюстрации - PNG/WebP с прозрачным фоном, фото - JPEG; нарезку движок делает сам. У каждой картинки - `alt` (`image_alt`, подпись в `![…]`).

**Обложка страницы** (картинка в выдаче и в соцсетях) выбирается полем: `og_image` (подпись `og_image_alt`), иначе `image`, иначе первая картинка во вводном блоке или `hero`, иначе `seo.og_default_image` (`20` §4.2, [«Обложка страницы»](../spec/20-data-contract.md#page-cover)). `alt` обязателен. Фото - от 1200 px по ширине, непрозрачное; файл только в `media/`, не в `static/`. Меньше 1200 px - отдаётся как есть, `heron check` предупреждает. Нет обложки - `og:image` не выводится, предупреждение, не ошибка.

## 6. Переезд

- старый адрес, содержимое которого переехало, - `redirect_from` у новой страницы, кириллицей или `%D0%…`;
- две-три старых страницы об одном - одна новая, все адреса в её `redirect_from`;
- адреса, которых больше нет, - в `gone` в `site.yaml`, не в странице.

Порядок переезда - гайд [05](../guide/05-seo.md#migrate-from-old-site).

Проверка: `heron check . --old-urls <файл>` - файл со старыми адресами (по строке на адрес или выгрузка Search Console). Адрес, который никуда не ведёт, попадёт в отчёт с подсказкой: добавить в `redirect_from` страницы или в `gone` (`21` §10, §11). Адрес сравнивается так, как его видит nginx: схема и хост отбрасываются, `%XX` и кириллица равны, со слешем и без - один адрес; регистр и языковой префикс различаются (`/About/` и `/about/` - разные адреса); параметры запроса учитываются только записями `gone` с параметром.

## 7. Языки

Перевод - файл с тем же именем в `content/<язык>/`. Нет перевода - страница остаётся на основном языке, в отчёте предупреждение. Основной язык не может быть пустым в проде (`E021`).

## Чек-лист

- [ ] у каждой страницы структуры есть файл; имена файлов одинаковы во всех языках
- [ ] `title`, `h1`, `description` заполнены и различаются; группа 2 заполнена
- [ ] ни одного выдуманного факта; непроверенное - в вопросы
- [ ] пустых секций-заглушек нет
- [ ] ссылки ключами; связи полями темы
- [ ] у картинок `alt`
- [ ] старые адреса разнесены по `redirect_from` и `gone`; `check --old-urls` без потерянных адресов
- [ ] обложка выбрана полем `image`/`og_image`, у неё `alt`
- [ ] `check` без ошибок; сводка «Не заполнено» - в отчёт
