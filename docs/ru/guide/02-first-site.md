# 02 · Первый сайт

Сквозной пример: от пустой папки до собранного сайта на двух языках - английский основной, русский второй. Нужен докер; без него - `pip install git+https://github.com/FMSTM/HERON.git@prod` и `heron` вместо `$H`.

```bash
H="docker run --rm -it -p 127.0.0.1:8000:8000 -v $PWD:/site -w /site --user $(id -u):$(id -g) ghcr.io/fmstm/heron:prod"
```

В zsh (по умолчанию на macOS) сначала выполните `setopt sh_word_split`, иначе `$H` не запустится.

- `-p 127.0.0.1:8000:8000` - для анкеты `setup` и просмотра `serve`: в контейнере они сами слушают все интерфейсы контейнера, а `127.0.0.1:` в начале публикует порт только на вашу машину, не в сеть. Без этого префикса docker открывает порт всем интерфейсам компьютера. Страница открывается на `localhost:8000`; адрес анкеты движок печатает вместе с ключом после `#` - открывайте его целиком;
- `-v $PWD:/site` - движок видит **только текущую папку**. Поэтому путь к сайту в командах - относительно неё: `мой-сайт`, или `.`, если вы уже в папке сайта. Путь вида `~/SOURCE/…` внутри контейнера не существует - движок так и скажет;
- `-it` - чтобы `new` мог задать вопросы. Без него он молча возьмёт значения по умолчанию;
- `--user` - иначе файлы окажутся во владении root, и править их вы не сможете.

Без терминала (агент, CI) и для команд рядом с запущенным `serve` нужна другая переменная: `-it` без терминала не стартует, а второй контейнер с тем же `-p` не запустится, пока порт занят.

```bash
H="docker run --rm -v $PWD:/site -w /site --user $(id -u):$(id -g) ghcr.io/fmstm/heron:prod"
```

## 1. Создать сайт

```bash
$H new мой-сайт          # новая папка рядом
$H new .                 # или в текущей - например, в только что склонированном git-репозитории
```

Папка может быть под git: `.git`, `.gitignore`, `README` и прочее служебное не мешают и не перезаписываются. Любой другой файл - отказ с перечнем того, что мешает.

`new` задаст несколько вопросов; Enter принимает значение в скобках:

```
Language you prefer to work in: hints, messages, comments in files
На каком языке вам удобнее работать: подсказки, сообщения, комментарии в файлах
  › (en, ru) [en] ru
Название сайта - как сайт называется для людей: в шапке, в <title>, в разметке
  › [мой-сайт] Workshop
Домен - без https:// и слешей, например example.com. Не знаете - Enter, останется заглушка
  › [workshop.example] workshop.example
Языки сайта - коды через запятую: en или en, ru. Каждый язык - папка content/<код>/
  › [en] en, ru
Основной язык - отдаётся из корня (/about/), остальные - с префиксом (/ru/about/)
  › [en] en
Итого: ...
Создать сайт? [Y/n]
```

Основной язык спрашивается, только если языков несколько. После вопросов `new` печатает блок «Итого» и просит подтверждение: Enter создаёт сайт.

- **язык работы** - на каком языке вам удобнее: на нём будут комментарии во всех файлах, которые положит движок, и сообщения на экране. Запоминается в `site.yaml` (`build.notes`). Задать заранее: `--notes ru` или `-e HERON_NOTES=ru`;
- **без вопросов** - флагами: `$H new мой-сайт --notes ru --name Workshop --domain workshop.example --lang en,ru -y`. Так работают агенты и CI; команду запускайте через переменную `H` без `-it` (см. выше).

В конце `new` печатает, что создал, и блок «Что дальше» с готовыми командами. Что появилось:

```
мой-сайт/
├── site.yaml                  конфиг с комментариями к каждому ключу
├── .gitignore                 что не попадает в git
├── heron-readme.md            записка: что это за папка - такая есть в каждой папке
├── AGENTS.md                  инструкция для AI-агента: роли, правила, «готово, когда»
├── CLAUDE.md  GEMINI.md       по одной строке «@AGENTS.md» - для агентов со своими именами файлов
├── agents/                    комплект для агента на вашем языке: README, роли, образцы, гайды,
│                              спецификации, схемы; в сборку и на сайт не попадает
├── content/en/index.md        главная с полным SEO-блоком
├── content/en/404.md          страница «не найдено»
├── content/en/blocks.md       демонстрационный сайт: «Блоки» - все виды блоков на одной странице,
├── content/en/themes.md       «Темы» - как сменить вид,
├── content/en/docs.md         «Документация» - где читать и главные команды
├── content/ru/…               то же для каждого языка из ответа
├── media/cover.png            обложка по умолчанию (seo.og_default_image)
├── media/demo/                две картинки к галерее на странице «Блоки»
├── data/  static/  plugins/
└── theme/                     стартовая тема: белая, рисует все формы - theme.yaml, шаблоны, модули, стили
```

Демонстрационные страницы приходят с темой: белая тема кладёт главную и три страницы-инструкции в каждый язык (тексты на русском и английском, другие языки получают английские). Откройте `blocks.md` рядом с `/blocks/` в браузере - файл и страница бок о бок. Выбрали в анкете другую тему - приедут её демонстрационные страницы, а ваши файлы не перезаписываются. Ненужные страницы удалите вместе с их ключами в `nav.main`.

Сайт уже собирается, и без единого предупреждения - можно проверить сразу: `$H build мой-сайт`.

**Инструкции для агента.** Если страницы будет писать AI-агент, ему достаточно ссылки на репозиторий сайта и фразы «прочитай `AGENTS.md` и работай в роли контента»: в `agents/` лежит документация движка ровно той версии и на том языке, что вы выбрали, а `agents/work/` - место для его отчёта и вопросов к вам. Папка невидима для сборки и ничего не весит на сайте; коммитьте её вместе с контентом. Не нужна - `$H new мой-сайт --no-agents` (запомнится в `site.yaml` как `build.agents: false`). Вышла новая версия движка - `$H init мой-сайт --agents` обновит файлы, которые вы не правили. Подробно - [`agents/README.md`](../README.md).

## 2. Описать сайт: анкета или `site.yaml`

Проще всего - анкетой:

```bash
$H setup мой-сайт
```

Откройте адрес, который напечатал движок, - `http://localhost:8000/#ключ`, целиком, вместе с ключом после `#`: без него анкета не откроет настройки. Дальше - название и домены, языки, о ком сайт (кто вы, сфера и специализация по schema.org, адрес, контакты), поиск, ИИ-ассистенты, аналитика, способ публикации, ключи, тема. «Сохранить» пишет `site.yaml`, не стирая ваших комментариев и ключей, которыми анкета не управляет, а по желанию - помощники: `.heron/scripts/build.sh`, `.heron/scripts/publish.sh`, `.gitignore` и workflow GitHub. Повторный запуск показывает записанное; прежняя версия файла сохраняется в `.heron-cache/setup/`. Страница анкеты двуязычная (кнопки EN и RU). Агент заполняет те же поля файлом: `$H setup мой-сайт --dump > answers.yaml`, правка, `$H setup мой-сайт --answers answers.yaml`. Подробно - [`21` §10](../spec/21-engine.md#heron-setup).

`site.yaml` - единственная точка правды о сайте, и править его руками тоже можно. Ответы на вопросы уже там; откройте его и допишите остальное - название на втором языке, суффикс заголовка, меню:

```yaml
site:
  domain: example.com
  name: Workshop
  name_ru: Мастерская         # название для русских страниц
  theme: main
  default_lang: en            # отдаётся из корня: /about/
  languages: [en, ru]         # второй язык - под /ru/
seo:
  title_suffix: " | Workshop"
  title_suffix_ru: " | Мастерская"
nav:
  main: ["/", about]          # ключи страниц: главная и about - на каждом языке свой адрес
```

Все ключи с пояснениями - [`20` §5](../spec/20-data-contract.md#site-yaml) и образец [`templates/site.yaml`](../templates/site.yaml).

## 3. Поменяли языки - догнать структуру

```bash
$H init мой-сайт
```

`init` читает `site.yaml` и дописывает недостающее: добавили в `languages` язык `de` - появятся `content/de/` со стартовыми и демонстрационными страницами темы и `theme/i18n/de.yaml`. Контент, тему и конфиг он не трогает (перезаписать - `--force`); `AGENTS.md`, где записаны языки сайта, обновляется вместе с манифестом `agents/heron-kit.yaml`. Если сайт создан с нужными языками сразу, этот шаг не нужен.

`init` в папке без `site.yaml` - например, с готовым контентом из другого места - задаёт те же вопросы, что и `new`, и предлагает языки по папкам, которые уже лежат в `content/`.

## 4. Написать главную

Откройте `content/en/index.md`. Наверху - SEO-блок: поменяйте `title` (для выдачи), `h1` (для того, кто уже на странице), `description` (сниппет). Комментарии не удаляйте - они подсказка тому, кто будет править файл после вас.

Ниже - вступление и секции:

```markdown
We repair roofs since 2010.

We come to measure on the day you call.

## What we do {#about}

- **Roof repair.** Patching and re-covering.
- **Gutters.** Installation and cleaning.
```

Русская главная - `content/ru/index.md`: тот же якорь `{#about}`, свой текст. Якорь - имя секции для темы, он одинаков во всех языках; заголовок переводится.

Какие секции и в каком виде рисует главная, решает тема. Стартовая выводит вступление и все секции подряд, кроме `section.note` (абзац под списком в стартовой теме не рисуется); на своей теме у каждой секции будет своё место и свой модуль - [04 · Тема и дизайн](04-theme.md).

## 5. Добавить страницу

Два способа, результат одинаковый:

```bash
cp мой-сайт/content/en/index.md мой-сайт/content/en/about.md   # и поправить значения
$H page page about мой-сайт                                    # тип page, файл content/en/about.md
```

`heron page <тип> <имя>` кладёт файл с полным SEO-блоком и заготовками всех секций, которые тема ждёт у этого типа. Страница сама появится в карте сайта и `llms.txt`; в меню - потому что её ключ `about` записан в `nav.main`.

Перевод - файл с тем же именем в `content/ru/` (`$H page page about мой-сайт --lang ru`). Адрес у перевода может быть свой - `slug: o-nas` в его SEO-блоке:

```
content/en/about.md   →  /about/
content/ru/about.md   →  /ru/o-nas/      slug: o-nas
```

Обе версии получат hreflang друг на друга, а пункт меню `about` на русских страницах сам поведёт на `/ru/o-nas/`.

## 6. Собрать и посмотреть

С пересборкой на каждое сохранение - `$H serve мой-сайт` и <http://localhost:8000>. Итоговая сборка в `dist/`:

```bash
$H build мой-сайт
docker run --rm -p 127.0.0.1:8080:8080 -v "$PWD/мой-сайт/dist:/usr/share/nginx/html:ro" \
  nginxinc/nginx-unprivileged:1.30.6-alpine@sha256:782bb89768cc87b7f95c18b95baa1af250e5d451f26794f59363540161147c01
```

Откройте <http://localhost:8080>. После сборки движок печатает отчёт: сколько страниц по языкам, предупреждения по группам (картинки, связи, ссылки, переводы…) и сводку незаполненных секций. Ошибки останавливают сборку и называют код и файл, строку - там, где она известна. Это голый nginx без конфига сайта: своей 404, 301 и 410 здесь нет, их проверяет `smoke` на образе - [06](06-deploy.md).

`$H check мой-сайт` - тот же отчёт без сборки.

## 7. Боевая сборка

```bash
$H build мой-сайт --env prod --strict
```

Если вы добавили страницу в §5, перед `build --env prod --strict` нужны её перевод и разные `title` и `h1`, иначе сборка вернёт rc=1.

`--env prod` открывает индексацию и включает счётчики из `analytics`. `--strict` превращает предупреждения в ошибки: в прод не уедет сайт с битой ссылкой или картинкой без `alt`. Готовая папка `dist/` кладётся на любой хостинг; как собрать образ nginx с сайтом - [06 · Сборка и выкладка](06-deploy.md).

## Где читать дальше

Документация той же версии, что движок, есть в образе: `$H docs` - оглавление, `$H docs --lang ru seo` - тема, `$H docs --search E023` - поиск. Схемы контрактов для редактора и агента: `$H schema --export <папка>`.
