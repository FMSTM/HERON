# {name}

Контент сайта на движке [HERON](https://github.com/FMSTM/HERON). Здесь только
контент: тексты, медиа, тема, конфигурация. Кода движка в этой папке нет:
сборкой, окружениями и упаковкой в образ занимается образ HERON. Ни Dockerfile,
ни compose, ни `.env` здесь не нужны и быть не должно.

## С чего начать

`site.yaml` - единственная точка правды о сайте: домен, языки, тема, меню,
версия движка. Структура папок следует за конфигом, а не наоборот: дописали
язык в `languages`, выполнили `init` - под него появились `content/<язык>/`
и `theme/i18n/<язык>.yaml`.

Удобнее заполнять его анкетой: `$H setup .` (нужен порт, как для `serve`)
задаёт название, домены, сведения о сайте, публикацию и тему и записывает их
сюда. Править файл руками тоже можно.

Пароли и токены в `site.yaml` не пишут: сборка статическая, и всё, что она
видит, может оказаться в HTML.

## Что где лежит

| Папка или файл | Что внутри |
|---|---|
| `site.yaml` | настройки сайта: домен, языки, меню, контакты, публикация |
| `content/<язык>/` | страницы в markdown, путь файла = адрес страницы |
| `media/` | всё, что показывает контент: изображения, видео, документы, фото обложек (от 1200 px) |
| `theme/` | как сайт выглядит: шаблоны, стили, строки интерфейса |
| `data/` | сквозные справочники в yaml, доступны шаблонам как `data.<имя>` |
| `static/` | файлы, которые обязаны лежать по точному адресу (не картинки) |
| `plugins/` | расширения сборки для этого сайта |
| `agents/` | инструкции для AI-агентов и место их отчётов `agents/work/`; в сборку не входит |
| `.heron/scripts/`, `.github/workflows/` | скрипты и автосборка, их пишет `heron setup` |
| `dist/` | результат сборки, в git не попадает |
| `AGENTS.md`, `CLAUDE.md`, `GEMINI.md` | точка входа агента и два указателя на неё; в сборку не входят |

В папках контента лежит `heron-readme.md` - короткая записка о том, что класть
туда и чего не класть. Движок эти файлы не замечает и в сайт не тащит.

## Порядок работы

Все команды идут через образ HERON. Один раз задайте короткие имена: `$H` для обычных команд, `$HP` для `setup` и `serve` (он публикует порт):

```bash
H="docker run --rm -v $PWD:/site -w /site --user $(id -u):$(id -g) ghcr.io/fmstm/heron:prod"
HP="docker run --rm -i -p 127.0.0.1:8000:8000 -v $PWD:/site -w /site --user $(id -u):$(id -g) ghcr.io/fmstm/heron:prod"
```

В zsh (по умолчанию на macOS) сначала выполните `setopt sh_word_split`, иначе
`$H` и `$HP` не запустятся.

Дальше из папки сайта:

```bash
$HP setup .                      # анкета: название, домены, публикация, тема
$H init .                        # папки догоняют site.yaml
$H check .                       # что заполнить и что поправить, без сборки
$HP serve .                      # посмотреть на localhost:8000
$H build . --env prod --strict   # собрать рабочую версию в dist/
```

Для просмотра `serve` образу нужен проброшенный порт: добавьте
`-p 127.0.0.1:8000:8000` к команде `docker run` в `H`.

Если сайтов несколько и у вас есть клон движка, из папки HERON один раз
выполните `cp env/.env.example env/.env.{slug}.dev`, заполните файл, и дальше
работайте через `./scripts/site.sh {slug} <команда>`.

Контента может не быть вовсе: пустой сайт собирается в dev и отдаёт robots.txt
и карту сайта. Прод-сборка без страниц падает с E017. Тему можно доводить, ещё не написав ни одной страницы.
