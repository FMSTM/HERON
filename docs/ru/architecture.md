# АРХИТЕКТУРА HERON

**Концепция:** движок отдельно от сайта. История изменений - CHANGELOG.md.

## Обзор

HERON - файловый движок сайтов. На вход папка с контентом, картинками, темой и одним конфигом. На выходе статический сайт в `dist/` или готовый образ nginx с этим сайтом внутри.

Движок **не копируется в сайт**. Он поставляется одним артефактом - образом `ghcr.io/fmstm/heron:<канал>` (теги: ветка-канал, версия) и тем же кодом как пакет для локальной разработки (`pip install git+https://github.com/FMSTM/HERON.git@<канал>`). Сайт объявляет нужную версию в `site.yaml`, движок отказывается собирать сайт, версию которого не поддерживает.

Движок делается сразу под несколько разных сайтов: спроектированный по одному, он вырождается в этот сайт с абстрактными именами переменных.

## Стек

Ядро: Python 3.12 · Jinja2 · markdown-it-py · PyYAML · pydantic · Pillow · click. Пакетный менеджер `uv`, линтер `ruff`, тесты `pytest`.

Обвязка: Docker · nginx · Bash.

Сервис форм (`heron-relay`, отдельный компонент, позже): FastAPI, без базы; SQLite подключается только как спул повторной отправки.

## Компоненты

- **`heron/core/`** - парсер markdown, дерево и URL, резолв связей, рендерер, обработка картинок
- **`heron/modules/`** - генераторы: sitemap, robots, llms.txt, JSON-LD, redirects, feed, конфиг nginx (`nginx.py`)
- **`heron/contracts/`** - pydantic-схемы `site.yaml`, `theme.yaml`, фронтматтера, версии движка; `schemas.py` - экспорт JSON Schema и реестра ошибок (`heron schema`)
- **`heron/cli.py`** - команды `new`, `init`, `check`, `serve`, `build`, `page`, `setup`, `theme`, `docs`, `schema`, `recipe`
- **`heron/setup/`** - анкета `heron setup`: модель ответов, запись `site.yaml` и файлов публикации, локальный сервер, классификатор сфер
- **`heron/schemaorg/`** - словарь schema.org 29.3 для проверки разметки (`SCH001`-`SCH006`)
- **`heron/themes/`** - установка и упаковка тем для `heron theme`: встроенная `starter` (файлы в `heron/scaffold/templates/`), каталог, ссылка, архив
- **`heron/messages.py`**, **`heron/texts/`** - тексты команд и сообщений ядра на ru и en
- **`heron/scaffold/`** - скелет сайта: тема, стартовые страницы, записки; `agents.py` - комплект для агентов (копия `docs/<язык>/`, схемы, манифест, корневые указатели)
- **`heron/docs.py`** - документация внутри пакета по языкам: `heron docs --lang`, темы, фолбэк на другой язык, выгрузка
- **`docs/{ru,en}/`** - единый источник документации: README комплекта, роли, образцы, гайды, спецификации; `docs/translation.yaml` - состояние перевода
- **`scripts/site.sh`** - сборка, упаковка в образ nginx, просмотр и проверка сайтов из репозитория движка; настройки в `env/.env.<сайт>.<окружение>`
- **`Dockerfile`, `Dockerfile.site`** - образ движка и образ сайта (он же `heron recipe`); **`.github/workflows/site-image.yml`** - общая сборка образа сайта; **`skills/`** - навыки для агентов; **`env/`** - настройки `site.sh`
- **папка сайта** - `site.yaml`, `content/`, `data/`, `media/`, `static/`, `theme/`, `plugins/`, комплект `agents/` с корневыми `AGENTS.md`, `CLAUDE.md`, `GEMINI.md` (сборка их не читает). Кода движка, Dockerfile и compose в ней нет. Анкета `heron setup` по выбору кладёт помощники `.heron/scripts/build.sh`, `.heron/scripts/publish.sh` и workflow `.github/workflows/image.yml` или `pages.yml`; длинная часть сборки остаётся в движке
- **`heron-relay`** - отдельный сервис приёма форм: почта, вебхук в CRM, Telegram. Разворачивается только там, где формы есть

## Решения

Поставка, формы, модель безопасности и каналы инструкций зафиксированы в [`spec/23-distribution.md`](spec/23-distribution.md); остальные решения записаны только здесь:

- сборщик статики вместо Django/Wagtail - сайту нечего обслуживать в рантайме
- ядро поставляется образом и версией, а не копией в каждом репозитории сайта: три копии ядра означают три расходящихся движка
- формы обслуживает отдельный сервис, а не движок: движок обязан остаться «один проход, без состояния, вышел»
- база данных не хранит ни контент, ни настройки сайта. Источник истины - файлы. Нарушение этого правила превращает HERON в WordPress
- макеты дизайна переводятся в Jinja2, рантайм макета в прод не идёт
- сборка идёт без сети: `--network=none`, ничего не докачивается на этапе build
- инструкции для агентов - один источник `docs/<язык>/`, четыре канала доставки (репозиторий, образ, папка сайта, сайт движка), копия байт в байт; документация на двух языках с тестом паритета (`spec/23-distribution.md` §12)

## Схема

```
                папка сайта
   site.yaml · content/ · data/ · media/ · static/ · theme/
   agents/ · AGENTS.md  (комплект для агентов - сборка не читает)
                     |
                     v
ghcr.io/fmstm/heron:<канал>  (образ или пакет; внутри - docs/ru, docs/en → heron docs)
     контракты -> парсер -> резолв -> рендер -> генераторы
                     |
          +----------+-----------+
          v                      v
        dist/               образ nginx
      (на хостинг)     (site.sh image на хосте)
          |
          v
        nginx  ------>  посетитель
                            |
                            v
                     heron-relay (позже)
                       |    |     |
                     почта  CRM  Telegram

   docs/<язык>/ ──▶ heron new/init ──▶ <сайт>/agents/        (копия, манифест с хешами)
                ──▶ пакет и образ   ──▶ heron docs --lang
                ──▶ CI сайта движка ──▶ sitebuilder.heron.software/agents/<язык>/, /schema/
                    (план, сырые файлы на сайте пока не опубликованы)
```

Сайт не зависит от `heron-relay`: сервис лежит - статика продолжает отдаваться, теряется только отправка формы.
