# {name}

Контент сайта на движке [HERON](https://github.com/FMSTM/HERON).

Здесь только контент: markdown, картинки, тема, конфигурация. Сборкой,
окружениями и упаковкой в образ занимается HERON — в этой папке нет и не
должно быть ни Dockerfile, ни compose, ни скриптов сборки, ни `.env`.

## site.yaml — единственная точка правды

Домен, языки, тема, меню, версия движка и публичные ID счётчиков объявлены
там и только там. Структура папок следует за конфигом, а не наоборот:
дописали язык в `languages` — выполните `init`, и под него появятся
`content/<язык>/` и `theme/i18n/<язык>.yaml`.

Пароли и токены в `site.yaml` не пишут: сборка статическая, и всё, что она
видит, может оказаться в HTML. SMTP форм и ключи деплоя живут в окружении
сборки, в `HERON/env/.env.<сайт>.<окружение>`.

## Порядок работы

Из папки HERON:

```bash
./scripts/site.sh {slug} init          # папки догоняют site.yaml
./scripts/site.sh {slug} build dev     # собрать в HERON/out/{slug}-dev/
./scripts/site.sh {slug} serve dev     # посмотреть на localhost:8080
./scripts/site.sh {slug} stop  dev
```

Путь к этой папке прописан в `HERON/env/.env.{slug}.dev`.

Контента может не быть вовсе — пустой сайт собирается и отдаёт robots.txt
и карту сайта. Тему можно доводить, ещё не написав ни одной страницы.

## Что где лежит

| Папка | Что внутри |
|---|---|
| `content/<язык>/` | страницы в markdown. Путь файла = адрес страницы |
| `data/` | справочники в yaml, доступны шаблонам как `data.<имя>` |
| `img/` | картинки-мастера 1:1, движок сам режет варианты |
| `static/` | favicon и прочее, копируется как есть |
| `theme/` | шаблоны, стили, строки интерфейса |
| `site.yaml` | домен, языки, тема, меню, версия движка, ID счётчиков |
