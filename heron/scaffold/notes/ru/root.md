# {name}

Контент сайта на движке [HERON](https://github.com/FMSTM/HERON). Здесь только
контент: тексты, медиа, тема, конфигурация. Кода движка в этой папке нет:
сборкой, окружениями и упаковкой в образ занимается образ HERON. Ни Dockerfile,
ни compose, ни `.env` здесь не нужны и быть не должно.

## С чего начать

`site.yaml` - единственная точка правды о сайте. В нём записано всё, что
относится к сайту целиком:

- домен, языки, тема, структура меню, версия движка;
- сведения для соцсетей и для AI-агентов;
- разметка schema.org - кто вы и чем занимаетесь;
- базовое SEO: то, что подставляется, пока страница в черновике, и то, что
  дописывается к каждой странице (например, окончание заголовка).

Структура папок следует за конфигом, а не наоборот: дописали язык в
`languages`, выполнили `init` - под него появились `content/<язык>/` и
`theme/i18n/<язык>.yaml`.

Заполнять `site.yaml` лучше встроенными средствами: `new` и `init` создают его
с комментариями, а конфигуратор (`setup`, команда ниже) спрашивает название,
домены, сведения о сайте, публикацию и тему и записывает ответы сюда. Идите
этим путём и следуйте рекомендациям в комментариях файла. Если уверены, что
понимаете, что делаете, `site.yaml` можно написать и руками - по справочнику:

- все настройки с пояснениями - [контракт данных, §5](https://github.com/FMSTM/HERON/blob/prod/docs/ru/spec/20-data-contract.md#site-yaml);
- полный образец - [templates/site.yaml](https://github.com/FMSTM/HERON/blob/prod/docs/ru/templates/site.yaml);
- пошагово - [«Первый сайт», шаг 3](https://github.com/FMSTM/HERON/blob/prod/docs/ru/guide/02-first-site.md).

Пароли и токены в `site.yaml` не пишут: сборка статическая, и всё, что она
видит, может оказаться в HTML.

## Что где лежит

| Папка или файл | Что внутри |
|---|---|
| `site.yaml` | настройки сайта: домен, языки, меню, контакты, публикация |
| `content/<язык>/` | страницы в markdown, путь файла = адрес страницы |
| `media/` | всё, что показывает контент: изображения, видео, документы, фото обложек (от 1200 px) |
| `theme/` | как сайт выглядит: шаблоны, стили, строки интерфейса |
| `data/` | сквозные справочники в yaml, доступны шаблонам как `data.<имя>` |
| `static/` | файлы, которые обязаны лежать по точному адресу (не картинки) |
| `plugins/` | расширения сборки для этого сайта |
| `agents/` | инструкции для AI-агентов и место их отчётов `agents/work/`; в сборку не входит |
| `.heron/scripts/`, `.github/workflows/` | скрипты и автосборка, их пишет `heron setup` |
| `dist/` | результат сборки, в git не попадает |
| `AGENTS.md`, `CLAUDE.md`, `GEMINI.md` | точка входа агента и два указателя на неё; в сборку не входят |

В папках контента лежит `heron-readme.md` - короткая записка о том, что класть
туда и чего не класть. Движок эти файлы не замечает и в сайт не тащит.

## Порядок работы

Все команды идут через Docker-образ HERON. Запускайте их из папки сайта.

### Какой образ брать

Версия движка - последнее слово в имени образа `ghcr.io/fmstm/heron:<версия>`:

- `:prod` - **по умолчанию**. Последний стабильный выпуск:
  функции отработаны, обратная совместимость проверена. Для рабочих сайтов
  всегда берите его;
- `:beta` - новинки до выпуска. Они могут долго не меняться,
  а потом в один момент что-то сломается. Это версия для экспериментаторов.

HERON - открытый проект. Нашли ошибку или хотите что-то добавить - присылайте
исправления в ветку `dev` [репозитория](https://github.com/FMSTM/HERON): мы
посмотрим код и примем его.

### Команды

Каждую команду можно просто скопировать строкой целиком:

```bash
docker run --rm -it -p 127.0.0.1:8000:8000 -v "$PWD:/site" -w /site --user "$(id -u):$(id -g)" ghcr.io/fmstm/heron:prod setup .
docker run --rm -v "$PWD:/site" -w /site --user "$(id -u):$(id -g)" ghcr.io/fmstm/heron:prod init .
docker run --rm -v "$PWD:/site" -w /site --user "$(id -u):$(id -g)" ghcr.io/fmstm/heron:prod check .
docker run --rm -it -p 127.0.0.1:8000:8000 -v "$PWD:/site" -w /site --user "$(id -u):$(id -g)" ghcr.io/fmstm/heron:prod serve .
docker run --rm -v "$PWD:/site" -w /site --user "$(id -u):$(id -g)" ghcr.io/fmstm/heron:prod build . --env prod --strict
```

- `setup` - конфигуратор: название, домены, публикация, тема. Откройте адрес,
  который он напечатает, целиком - с ключом после «#»;
- `init` - папки догоняют `site.yaml`;
- `check` - что заполнить и что поправить, без сборки;
- `serve` - посмотреть сайт в браузере на <http://localhost:8000>;
- `build . --env prod --strict` - собрать рабочую версию в `dist/`.

У `setup` и `serve` в команде есть `-p 127.0.0.1:8000:8000`: он пробрасывает
порт 8000 из контейнера на ваш компьютер, иначе страницу не открыть в
браузере. Остальным командам порт не нужен.

### Короче: имя `heron` на время работы

Чтобы не копировать длинную строку каждый раз, задайте один раз в терминале
короткое имя - alias:

```bash
alias heron='docker run --rm -it -v "$PWD:/site" -w /site --user "$(id -u):$(id -g)" ghcr.io/fmstm/heron:prod'
```

Теперь `heron` в начале команды подставляет всю эту строку: `heron init .`,
`heron check .`, `heron build . --env prod --strict`. Порта в имени нет,
поэтому `setup` и `serve` по-прежнему запускайте полной командой из списка выше.

Имя живёт, пока открыт этот терминал. Убрать раньше - `unalias heron`.
Нужно насовсем - раздел «Если собираете сайты регулярно» в
[«Установке»](https://github.com/FMSTM/HERON/blob/prod/docs/ru/guide/00-install.md).
Движок поставлен без Docker - команда `heron` у вас уже есть, alias не нужен.

### Если сайтов несколько

Для тех, кто держит несколько сайтов на одном сервере, в репозитории движка
есть скрипт `site.sh` (папка `scripts/`). Он хранит настройки каждого сайта в отдельном
файле в папке `env/` репозитория и поднимает для сайта контейнеры dev и prod.
Нужен клон репозитория HERON: из его папки один раз выполните
`cp env/.env.example env/.env.{slug}.dev`, заполните файл и дальше работайте
через `./scripts/site.sh {slug} <команда>`. Подробно - в разделе
[«Сборка и выкладка»](https://github.com/FMSTM/HERON/blob/prod/docs/ru/guide/06-deploy.md).
Если сайт один, скрипт не нужен.

Контента может не быть вовсе: пустой сайт собирается в dev и отдаёт robots.txt
и карту сайта. Боевая сборка (prod) без страниц падает с E017. Тему можно
доводить, ещё не написав ни одной страницы.

## Если нужен агент

Если вы работаете с AI-агентом, дайте ему ссылку на репозиторий сайта и на
открытый [репозиторий HERON](https://github.com/FMSTM/HERON) и фразу
«прочитай AGENTS.md». В репозитории HERON - все инструкции и
[готовые навыки (skills)](https://github.com/FMSTM/HERON/tree/prod/skills)
для каждой роли: с ними результат выше среднего получается и при базовых
навыках промптинга. Свой отчёт агент сдаст в `agents/work/`.
