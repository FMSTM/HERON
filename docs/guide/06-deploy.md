# 06 · Сборка и выкладка

Как собрать сайт для прода, упаковать его в образ и вести несколько сайтов на разных версиях движка. Для того, кто выкладывает, — человека или агента-сборщика.

## Два выхода: папка или образ

| | Папка `dist/` | Образ nginx |
|---|---|---|
| Чем | `heron build` | `scripts/site.sh <сайт> image` |
| Что внутри | HTML, картинки, карты, `.heron-nginx.conf` | nginx-unprivileged, статика, конфиг под этот сайт |
| Куда | любой хостинг статики, свой nginx | любой хост с докером, k8s |
| 301, 410, своя 404 | подключить `.heron-nginx.conf` в свой nginx | уже включены |

Выход выбирается командой, а не при создании сайта: одна и та же папка собирается и так, и так. → [`23` §5](../spec/23-distribution.md#5-два-выхода-папка-и-образ)

## Окружение сайта

Дев и прод — это **флаг сборки**, а не другой образ движка:

| | `--env dev` (по умолчанию) | `--env prod` |
|---|---|---|
| индексация | закрыта: `noindex` и `Disallow: /` | открыта |
| счётчики из `analytics` | нет | есть |
| метка сборки (версия, время, коммит) | тема может показать | не показывается |

`--strict` превращает предупреждения в ошибки — для прода обязателен. Перебить по отдельности: `SITE_INDEXABLE=false`, `SITE_ANALYTICS=false` — прод-подобное превью, закрытое от поисковиков.

## Один сайт

```bash
H="docker run --rm -v $PWD:/site -w /site --user $(id -u):$(id -g) ghcr.io/fmstm/heron:prod"
$H build мой-сайт --env prod --strict
```

`мой-сайт/dist/` — готовый сайт. Подключите `dist/.heron-nginx.conf` в свой `server {}` или залейте папку на хостинг статики (тогда 301/410 настраиваются средствами хостинга по `dist/redirects.map` и `dist/gone.map`).

Посмотреть локально — `heron serve мой-сайт`: та же 404, что увидит посетитель, сборка во временную папку, папка сайта не пачкается. 301 и 410 `serve` не изображает — их проверяет `smoke` на образе.

## Несколько сайтов: `scripts/site.sh`

Из клона репозитория движка:

```bash
git clone https://github.com/FMSTM/HERON.git && cd HERON
HERON_NOTES=ru ./scripts/site.sh мойсайт new ~/sites/мой-сайт
```

`new` создаёт папку сайта — в терминале с теми же вопросами, что и `heron new`, — и заводит `env/.env.мойсайт.dev` и `.prod`. Папка может уже существовать и быть под git. Дальше всё — одной командой:

```bash
./scripts/site.sh мойсайт check dev     # отчёт без сборки
./scripts/site.sh мойсайт build dev     # → out/мойсайт-dev
./scripts/site.sh мойсайт serve dev     # nginx на localhost:$PORT
./scripts/site.sh мойсайт stop          # погасить просмотр
./scripts/site.sh мойсайт build prod
./scripts/site.sh мойсайт image prod    # образ IMAGE_NAME:IMAGE_TAG
./scripts/site.sh мойсайт smoke prod    # поднять образ, проверить коды
./scripts/site.sh мойсайт push prod     # в REGISTRY
./scripts/site.sh мойсайт init          # достроить папку после правки site.yaml
```

Папка контента монтируется **только на чтение**: всё, что производит сборка, живёт в `out/`, контент ничем не пачкается.

Настройки сайта — `env/.env.<сайт>.<окружение>`, в гит не попадают. Образец с пояснениями — [`env/.env.example`](../../env/.env.example):

| Переменная | Что задаёт |
|---|---|
| `SITE_PATH` | путь к папке сайта |
| `SITE_ENV` | `dev` или `prod` — каким будет сайт |
| `STRICT` | строгая сборка |
| `ENGINE` | каким движком собирать (ниже) |
| `IMAGE_NAME`, `IMAGE_TAG` | имя образа сайта |
| `REGISTRY`, `REGISTRY_CONFIG` | реестр для `push` и докер-конфиг для него; пусто — `push` запрещён |
| `PORT` | порт просмотра |
| `HERON_NOTES` | язык комментариев и записок, которые кладёт `init`: `ru` или `en` |

Секреты форм (SMTP, вебхуки) сюда не кладутся: сборка статическая, всё, что она видит, может оказаться в HTML.

## Дымовой прогон

`site.sh <сайт> smoke <окружение>` поднимает собранный образ и сверяет ответы:

- корень и `robots.txt` — 200, несуществующий адрес — 404;
- языковой раздел — 200 и своя 404;
- служебный конфиг рядом со статикой — 404;
- **каждый** адрес из `redirects.map` — 301 туда, куда объявлено;
- **каждый** точный адрес из `gone.map` — 410.

Упал — контейнер гасится, логи nginx печатаются. → [`23` §5, «Проверки и дымовой прогон»](../spec/23-distribution.md#проверки-и-дымовой-прогон)

## Версии движка

**Сайт закрепляет движок сам** — первой строкой `site.yaml`:

```yaml
heron: ">=0.1,<0.2"
```

Движок не из диапазона откажется собирать (`E012`). Обновление движка для сайта — смена этой строки, осознанно и по одному сайту.

**Каким движком собирает `site.sh`** — `ENGINE` в env-файле:

| Значение | Когда |
|---|---|
| пусто | точная версия из `site.yaml`, если она там точная; иначе исходники рядом; иначе `:prod` |
| `ghcr.io/fmstm/heron:prod` | стабильный — обычный выбор |
| `ghcr.io/fmstm/heron:0.1.0` | закрепиться на версии |
| `source` | собрать из исходников рядом — только когда правите сам движок |

**Теги образа движка:**

| Тег | Что это |
|---|---|
| `:X.Y.Z` | точная версия, не меняется никогда |
| `:prod` | то, на чём стоят сайты |
| `:beta` | обкатка следующей версии на живых сайтах |
| `:dev` | разработка движка; для сайтов не предназначен |

Какой образ на руках, показывает `--version`: ветка, коммит и время сборки, например `heron, version 0.1.0 (beta, 55249f0, 2026-10-08 19:12 UTC)`. Номер версии один на всю ветку разработки, а по коммиту видно, свежая ли бета. Из исходников — `(source, <коммит>)`.

Подвижного `:X.Y` нет намеренно: сайт должен иметь возможность закрепиться на том, что не поедет под ним завтра.

## Чек-лист перед выкладкой

1. `site.yaml`: домен, языки, `heron:` с диапазоном, счётчики.
2. `build --env prod --strict` проходит без ошибок.
3. Сводка «Не заполнено» пуста или осознанно принята.
4. `smoke prod` зелёный: 200, 404, все 301 и 410.
5. После выкладки — карта сайта в Search Console.
