# 02 · Первый сайт

Сквозной пример: от пустой папки до собранного сайта на двух языках — английский основной, русский второй. Нужен докер; без него — `pip install git+https://github.com/FMSTM/HERON.git@prod` и `heron` вместо `$H`.

```bash
H="docker run --rm -it -v $PWD:/site -w /site --user $(id -u):$(id -g) ghcr.io/fmstm/heron:prod"
```

- `-v $PWD:/site` — движок видит **только текущую папку**. Поэтому путь к сайту в командах — относительно неё: `мой-сайт`, или `.`, если вы уже в папке сайта. Путь вида `~/SOURCE/…` внутри контейнера не существует — движок так и скажет;
- `-it` — чтобы `new` мог задать вопросы. Без него он молча возьмёт значения по умолчанию;
- `--user` — иначе файлы окажутся во владении root, и править их вы не сможете.

## 1. Создать сайт

```bash
$H new мой-сайт          # новая папка рядом
$H new .                 # или в текущей — например, в только что склонированном git-репозитории
```

Папка может быть под git: `.git`, `.gitignore`, `README` и прочее служебное не мешают и не перезаписываются. Любой другой файл — отказ с перечнем того, что мешает.

`new` задаст несколько вопросов; Enter принимает значение в скобках:

```
Notes and messages language / Язык пояснений и сообщений
  › (en, ru) [en] ru
Название сайта — как сайт называется для людей: в шапке, в <title>, в разметке
  › [мой-сайт] Workshop
Домен — без https:// и слешей, например example.com. Не знаете — Enter, останется заглушка
  › [workshop.example] workshop.com
Языки сайта — коды через запятую: en или en, ru. Каждый язык — папка content/<код>/
  › [en] en, ru
Основной язык — отдаётся из корня (/about/), остальные — с префиксом (/ru/about/)
  › [en] en
```

- **язык пояснений** — на нём будут комментарии во всех файлах, которые положит движок, и сообщения на экране. Запоминается в `site.yaml` (`build.notes`). Задать заранее: `--notes ru` или `-e HERON_NOTES=ru`;
- **без вопросов** — флагами: `$H new мой-сайт --notes ru --name Workshop --domain workshop.com --lang en,ru -y`. Так работают агенты и CI.

В конце `new` печатает, что создал, и блок «Что дальше» с готовыми командами. Что появилось:

```
мой-сайт/
├── site.yaml                  конфиг с комментариями к каждому ключу
├── heron-readme.md            записка: что это за папка — такая есть в каждой папке
├── content/en/index.md        главная с полным SEO-блоком
├── content/en/404.md          страница «не найдено»
├── content/ru/…               то же для каждого языка из ответа
├── media/  data/  static/  plugins/
└── theme/                     стартовая тема: theme.yaml, base.html, шаблоны, модули, стили
```

Сайт уже собирается, и без единого предупреждения — можно проверить сразу: `$H build мой-сайт`.

## 2. Описать сайт в `site.yaml`

`site.yaml` — единственная точка правды о сайте. Ответы на вопросы уже там; откройте его и допишите остальное — название на втором языке, суффикс заголовка, меню:

```yaml
site:
  domain: example.com
  name: Workshop
  name_ru: Мастерская         # название для русских страниц
  theme: main
  default_lang: en            # отдаётся из корня: /about/
  languages: [en, ru]         # второй язык — под /ru/
seo:
  title_suffix: " — Workshop"
  title_suffix_ru: " — Мастерская"
nav:
  main: ["/", about]          # ключи страниц: главная и about — на каждом языке свой адрес
```

Все ключи с пояснениями — [`20` §5](../spec/20-data-contract.md#5-siteyaml) и образец [`docs/agents/templates/site.yaml`](../agents/templates/site.yaml).

## 3. Поменяли языки — догнать структуру

```bash
$H init мой-сайт
```

`init` читает `site.yaml` и дописывает недостающее: добавили в `languages` язык `de` — появятся `content/de/index.md`, `content/de/404.md` и `theme/i18n/de.yaml`. Существующие файлы он не трогает (перезаписать — `--force`). Если сайт создан с нужными языками сразу, этот шаг не нужен.

## 4. Написать главную

Откройте `content/en/index.md`. Наверху — SEO-блок: поменяйте `title` (для выдачи), `h1` (для того, кто уже на странице), `description` (сниппет). Комментарии не удаляйте — они подсказка тому, кто будет править файл после вас.

Ниже — вступление и секции:

```markdown
We repair roofs since 2010.

We come to measure on the day you call.

## What we do {#about}

- **Roof repair.** Patching and re-covering.
- **Gutters.** Installation and cleaning.
```

Русская главная — `content/ru/index.md`: тот же якорь `{#about}`, свой текст. Якорь — имя секции для темы, он одинаков во всех языках; заголовок переводится.

Какие секции и в каком виде рисует главная, решает тема. Стартовая выводит вступление и все секции подряд; на своей теме у каждой секции будет своё место и свой модуль — [04 · Тема и дизайн](04-theme.md).

## 5. Добавить страницу

Два способа, результат одинаковый:

```bash
cp мой-сайт/content/en/index.md мой-сайт/content/en/about.md   # и поправить значения
$H page page about мой-сайт                                    # тип page, файл content/en/about.md
```

`heron page <тип> <имя>` кладёт файл с полным SEO-блоком и заготовками всех секций, которые тема ждёт у этого типа. Страница сама появится в карте сайта и `llms.txt`; в меню — потому что её ключ `about` записан в `nav.main`.

Перевод — файл с тем же именем в `content/ru/` (`$H page page about мой-сайт --lang ru`). Адрес у перевода может быть свой — `slug: o-nas` в его SEO-блоке:

```
content/en/about.md   →  /about/
content/ru/about.md   →  /ru/o-nas/      slug: o-nas
```

Обе версии получат hreflang друг на друга, а пункт меню `about` на русских страницах сам поведёт на `/ru/o-nas/`.

## 6. Собрать и посмотреть

```bash
$H build мой-сайт
docker run --rm -p 8080:8080 -v "$PWD/мой-сайт/dist:/usr/share/nginx/html:ro" \
  nginxinc/nginx-unprivileged:1.27-alpine
```

Откройте <http://localhost:8080>. После сборки движок печатает отчёт: сколько страниц по языкам, предупреждения по группам (картинки, связи, ссылки, переводы…) и сводку незаполненных секций. Ошибки останавливают сборку и называют файл и строку.

`$H check мой-сайт` — тот же отчёт без сборки.

## 7. Боевая сборка

```bash
$H build мой-сайт --env prod --strict
```

`--env prod` открывает индексацию и включает счётчики из `analytics`. `--strict` превращает предупреждения в ошибки: в прод не уедет сайт с битой ссылкой или картинкой без `alt`. Готовая папка `dist/` кладётся на любой хостинг; как собрать образ nginx с сайтом — [06 · Сборка и выкладка](06-deploy.md).
