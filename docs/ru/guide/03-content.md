# 03 · Страницы и контент

В этом разделе - всё о страницах: из чего состоит файл страницы, как добавить новую страницу и целый раздел, как писать секции, ссылки, картинки и переводы. Он для тех, кто ведёт сайт и пишет тексты, - человека или AI-агента.

Мы продолжаем сайт из [02 · Первый сайт](02-first-site.md): команды запускаются из папки `~/sites`, сайт лежит в `мой-сайт`.

> **Поставили движок без Docker?** Тогда в каждой команде всё, что стоит до имени образа (`ghcr.io/fmstm/heron:…`) включительно, замените словом `heron`. Подробнее - [в разделе об установке](00-install.md#without-docker).

## Из чего состоит страница

Каждая страница - один markdown-файл в папке `content/<язык>/`. Путь файла определяет адрес страницы. Например, файл `content/en/services/roof.md` на сайте с `default_lang: en` откроется по адресу `/services/roof/`. Вот как он выглядит:

```markdown
---
# ================= 1. ОСНОВНОЕ =================
title: "Roof repair in Springfield"     # в выдаче, до 60 знаков
h1: "Roof repair, start to finish"      # заголовок на странице
description: "Patching, re-covering, one-year warranty."
…группы 2-8…
---

We have been repairing roofs in Springfield since 2010.

We come out to inspect the roof the same day you call.

## What is included {#includes}

- **Inspection.** We come the day you call.
- **Repair.** Patching or full re-covering.

## FAQ {#faq}

### How much does it cost?

We quote after the inspection.
```

Его русский перевод - файл `content/ru/services/roof.md`: тот же SEO-блок, но с русскими значениями, те же якоря `{#includes}` и `{#faq}`, русские заголовки. Комментарии в SEO-блоке написаны на языке работы, который вы выбрали при создании сайта (`new --notes`), а не на языке страницы.

В файле три части, и они всегда идут в этом порядке:

1. **SEO-блок** - всё между строками `---` в начале файла. Он разбит на восемь групп. Обязательны только `title`, `h1` и `description`, остальное заполняют по необходимости. Все поля, их значения по умолчанию и что с ними делает движок - в одной таблице: [`20` §4.2](../spec/20-data-contract.md#frontmatter).
2. **Вступление** - текст до первого заголовка, не больше двух абзацев. Тема получает первый абзац как `lead` (подводка), второй - как `promise` (обещание).
3. **Секции** - каждая начинается со строки `## Заголовок {#якорь}`. Заголовок видит посетитель, а якорь - это имя секции для темы: по нему тема понимает, где и как секцию показать. Заголовок можно менять как угодно, якорь - нет.

## Новая страница

Проще всего создать страницу командой `page add`:

```bash
docker run --rm -it -v "$PWD:/site" -w /site --user "$(id -u):$(id -g)" ghcr.io/fmstm/heron:prod page add about мой-сайт
```

После `page add` идут **ключ** страницы (`about`; если страница лежит в папке раздела, ключ - папка плюс имя, например `services/roof`) и папка сайта. Правило у команды одно: страницы нет - она создаётся сразу на всех языках сайта, есть - открывается на правку. Движок спросит поля по порядку - категорию, тип (если в теме их несколько), заголовки, описание, меню, обложку, тексты секций - с подсказкой у каждого, значением по умолчанию (Enter его оставляет) и справкой по `?`. Затем - переводы на остальные языки: Enter пропускает поле, и такой язык получает пометку `translation: pending` (ниже). В файле будут полный SEO-блок и заготовки всех секций, которые тема ждёт у этого типа. Можно и без команды: скопируйте готовый файл под новым именем в каждую папку языка.

Агенту и скриптам вопросы не нужны: `--dump` печатает все поля страницы в YAML, `--answers файл` записывает ответы из файла (те же поля по языкам), а `--lang de` правит только один язык. Без терминала и без ответов команда создаёт страницу по заготовке, а существующую не трогает.

Дальше:

- поменяйте `title`, `h1` и `description`. Заполните группу 2 «ключевые запросы»: движок её не читает, но она помогает держать правило «один запрос - одна страница», чтобы две страницы не спорили в поиске за одно и то же;
- напишите вступление и секции. Если для секции нет материала - **не создавайте её**: пустой блок тема не рисует, а сводка «Не заполнено» после сборки покажет, чего не хватает;
- соберите сайт. Страница сама появится в каталоге своего раздела, в карте сайта, в ссылках между переводами (hreflang) и в `llms.txt`.

**Перевод не готов.** Если при создании перевод пропущен, файл языка получает текст основного языка и строку `translation: pending` в группе 7 SEO-блока. Черновая сборка и просмотр показывают такую страницу с жёлтой плашкой «перевод не готов», а боевая сборка (`--env prod`) её на этом языке не публикует: нет ни страницы, ни ссылок на неё в меню, карте сайта и hreflang; отчёт сборки называет такие страницы списком, а с `--strict` это ошибка. Перевели - удалите строку, и страница появится.

Чтобы удалить страницу, удалите её файл. Если старый адрес уже был в поиске, не бросайте его: впишите этот адрес в `redirect_from` страницы, которая её заменяет (посетителя перенаправит, код 301), или в `gone` в `site.yaml` (адрес ответит «удалено навсегда», код 410).

## Разделы

Раздел - это папка со страницами и отдельной страницей самого раздела, файлом `_index.md`. Например, раздел «Услуги»:

```
content/en/services/_index.md      →  /services/                каталог
content/en/services/roof.md        →  /services/roof/
content/en/services/gutter.md      →  /services/gutter/
content/ru/services/_index.md      →  /ru/uslugi/               slug: uslugi
content/ru/services/roof.md        →  /ru/uslugi/krovlya/       slug: krovlya
content/ru/services/gutter.md      →  /ru/uslugi/vodostok/      slug: vodostok
```

Раздел (категорию) создаёт `category add` - сразу на всех языках, с его страницей `_index.md`, видом списка страниц и типом страниц внутри; вложенный раздел - путём через `/`:

```bash
docker run --rm -it -v "$PWD:/site" -w /site --user "$(id -u):$(id -g)" ghcr.io/fmstm/heron:prod category add services мой-сайт
```

Страницу сразу в нужный раздел кладёт флаг `--category` (раздела нет - он создастся):

```bash
docker run --rm -it -v "$PWD:/site" -w /site --user "$(id -u):$(id -g)" ghcr.io/fmstm/heron:prod page add roof --category services мой-сайт
```

Тот же флаг у существующей страницы - перенос: файлы переезжают на всех языках, а со старых адресов ставится 301 (`redirect_from`). Так же переносится раздел целиком - со всеми страницами внутри.

Что важно знать о разделах:

- `slug` в `_index.md` меняет адрес и самого раздела, и всех страниц в нём: русские страницы раздела сами окажутся под `/ru/uslugi/`;
- в `_index.md` можно задать тип для всех страниц раздела, например `children_type: service` - если такой тип есть в теме (в стартовой белой теме только `home`, `page` и `404`, с чужим типом сборка остановится с ошибкой `E008`). Тогда тема нарисует их своим шаблоном;
- страница раздела получает список своих страниц как `page.children`. Они отсортированы по полю `order`, а при равном `order` - по `h1`;
- постраничного деления нет: раздел - одна страница. Большой раздел делят на подразделы - вложенными папками.

Если страница относится сразу к нескольким разделам, её не вкладывают ни в один. Её кладут на верхний уровень и связывают с разделами полями связей (о них ниже) - так адрес страницы не зависит от того, в скольких местах она показана.

## Формы секций

Вы пишете секцию обычным markdown, а движок сам понимает по разметке, что это - список, шаги, вопросы-ответы - и отдаёт теме уже разобранные данные. Такой вид секции называется **формой**:

| Разметка | Форма |
|---|---|
| абзацы | `prose` |
| `- пункт`, `- **Термин.** Пояснение` | `list` |
| `1. **Шаг.** Текст` | `steps` |
| `### Вопрос?` и ответ под ним | `faq` (и `FAQPage` в разметке) |
| `Ключ \| Значение` построчно | `facts` |
| markdown-таблица | `table` |
| две группы `###` со списками | `two-lists` |
| три и больше групп `###` со списками | `checklist` |
| `> цитата` без списка | `callout` |

Ещё четыре формы движок по разметке не угадывает - их задают классом в якоре:

- `{#flags .alert}` - `alert-list`;
- `{#plan .timeline}` - `timeline`;
- `{#photos .gallery}` - `gallery`. Нужен маркированный список картинок: `- ![подпись](media/a.png)`; абзац с картинкой даст прозу и предупреждение;
- `{#options .tabs}` - `tabs`: группы `###` с любым содержимым.

Полная таблица форм, порядок, в котором движок их распознаёт, и что именно получает тема - [`20` §4.4](../spec/20-data-contract.md#section-forms).

### Когда движок угадывает не то

Форма определяется по разметке, а разметка иногда говорит не то, что вы имели в виду. Класс в якоре всегда сильнее догадки движка:

| Вы написали | Движок решил | Вы имели в виду | Как сказать |
|---|---|---|---|
| текст с подзаголовками `###`, без списков | `faq`: подзаголовок - вопрос, текст - ответ | прозу с подзаголовками | `## О нас {#about .prose}` |
| две группы `###` со списками | `two-lists`: «подходит / не подходит» | перечень, например документы в двух группах | `## Документы {#docs .checklist}` |
| строки `ключ \| значение` | `facts` | шкалу «период - событие» | `## Восстановление {#recovery .timeline}` |
| список и цитата под ним | `list`, цитата - в `section.callout` | - | так и задумано |
| список и абзац под ним | `list`, абзац - в `section.note` | текст на странице | стартовая тема `note` не рисует: текст на страницу не попадёт; поставьте абзац до списка (`section.lead`) или выведите `section.note` в своём модуле |

У `facts` можно сделать подводку - абзац перед строками «ключ | значение». Тема получит его как `section.lead`:

```markdown
## Коротко {#quick .facts}

The format in short:

Format | in person
Term   | about a month
```

Тема может заранее сказать, какую форму она ждёт у секции, - в `theme.yaml` (`uses: ["docs:checklist"]`). Если пришла другая, отчёт после сборки скажет «ждали checklist, пришло two-lists». Поправьте класс в якоре или форму в `uses` - смотря кто прав. А если шаблон темы вызывает модуль формы напрямую (например, `mod.steps("how")` на секции, которая на деле проза), сборка остановится с ошибкой `E010`.

## Ссылки

Ссылку на свою страницу пишите **от корня сайта и без языковой приставки**. Лучше всего - ключом, то есть путём файла:

```markdown
[roof repair](/services/roof/)        в content/en/…  →  /services/roof/
[ремонт кровли](/services/roof/)      в content/ru/…  →  /ru/uslugi/krovlya/
[home](/)                             в content/en/…  →  /
[на главную](/)                       в content/ru/…  →  /ru/
```

В обоих языках пишется одно и то же - ключ, а движок сам подставит адрес на языке страницы, со всеми `slug`. Что ещё он делает:

- нет перевода страницы - ссылка поведёт на версию основного языка, а в отчёте будет предупреждение;
- ссылка ведёт в никуда - предупреждение с файлом и строкой;
- внешние адреса, ссылки на `/media/…` и якоря он не трогает.

Подробнее - [`20` §2, «Ссылки внутри контента»](../spec/20-data-contract.md#links-relative-to-language).

## Связи между страницами

Блоки «Смотрите также», «Услуги по теме», «Где упоминается» не нужно собирать ссылками вручную. Тема объявляет в `theme.yaml` поле связи, а страница перечисляет в нём имена файлов других страниц:

```yaml
related:                 # в SEO-блоке, группа 8
  - gutter
  - slug: inspection
    note: Not sure where to start? Begin here
```

Во второй форме - `slug:` с `note:` - к ссылке добавляется подпись. Здесь `slug` - не адрес, а тот же ключ (имя файла) страницы: так поле называется исторически. Дальше движок всё сделает сам: проверит, что такие страницы есть (если нет - ошибка `E006`), отдаст теме карточки с подписями и построит обратный список у тех страниц, на которые сослались.

Подробнее - [`20` §6, «Связи»](../spec/20-data-contract.md#theme-yaml).

## Картинки, видео, документы

Все файлы - в папке `media/`. Путь к ним пишется от корня сайта, со слешем в начале или без: `media/a.png` и `/media/a.png` движок считает одним адресом.

Картинка-превью страницы для каталога задаётся в SEO-блоке:

```yaml
image: media/services/roof.png        # превью в каталоге
image_alt: "Roof after the repair"
```

В тексте страницы картинки и документы - обычной разметкой markdown:

```markdown
![Gutter layout](media/services/gutter.png)
[Checklist in PDF](media/docs/memo.pdf)
```

С картинками движок работает сам:

- нарезает их под пропорции и ширины, которые просит тема, делает версии в WebP и AVIF и проставляет размеры;
- иллюстрации (с прозрачным фоном) вписывает в пропорцию целиком, фотографии кадрирует;
- если файла нет - ошибка `E007` с именем страницы; если файл лежит в `media/`, но на него никто не ссылается, - строка в отчёте.

Видео задаётся полями `video` и `video_poster` (картинка, которую видно до запуска). Подробнее - [`20` §7](../spec/20-data-contract.md#images).

## Языки и переводы

Перевод страницы - файл с тем же именем в папке другого языка, например `content/ru/services/roof.md`. Свой адрес у перевода задаётся полем `slug: krovlya`.

Переводы связаны между собой именем файла, поэтому смена `slug` эту связь не рвёт. Обе версии получают ссылки друг на друга для поисковиков (hreflang), а версией по умолчанию (`x-default`) считается версия основного языка, в нашем примере - английская. Если языка нет в `site.languages`, его папку движок не читает.

Подробнее - [`20` §3](../spec/20-data-contract.md#languages).

## Что не пишут в страницах

Некоторые вещи повторяются на многих страницах, поэтому их держат в одном месте:

- телефон, адрес, часы работы, соцсети - блоки `contact` и `organization` в `site.yaml`. Тема и разметка для поисковиков берут их оттуда, поэтому в шапке и подвале они всегда одинаковые;
- отзывы, команда, цифры - файлы `data/*.yaml`;
- меню - `nav` в `site.yaml`;
- удалённые адреса, которые должны отвечать 410, - `gone` в `site.yaml`.
