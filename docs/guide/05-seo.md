# 05 · SEO

Что HERON генерирует сам, что заполняете вы и как переехать со старого сайта, не потеряв выдачу. Для того, кто отвечает за поиск, — человека или агента контента и SEO.

## Что генерируется само

Ничего из этого не пишется руками и не лежит файлом — собирается на каждой сборке из страниц и `site.yaml`, поэтому не устаревает:

| Что | Откуда | Подробно |
|---|---|---|
| `<title>`, meta description, canonical | `title` + `seo.title_suffix`, `description`, адрес страницы | [`20` §4.2](../spec/20-data-contract.md#42-фронтматтер) |
| Open Graph и Twitter | поля групп 3–4, иначе `title`/`description`/`seo.og_default_image` | [`20` §4.2](../spec/20-data-contract.md#42-фронтматтер) |
| `sitemap.xml` | все опубликованные индексируемые страницы, `lastmod` из `updated` | [`21` §9](../spec/21-engine.md#sitemap) |
| hreflang в `<head>` и в карте | переводы по имени файла, `x-default` — язык по умолчанию | [`20` §3](../spec/20-data-contract.md#3-языки) |
| `robots.txt` | `seo.robots_extra` + строка `Sitemap:` | [`21` §9](../spec/21-engine.md#robotstxt) |
| JSON-LD | тип от темы, данные от страницы и блока `schema` в `site.yaml`, крошки, FAQ | [`21` §9](../spec/21-engine.md#json-ld) |
| `llms.txt`, `llms-full.txt` | дерево страниц, `description`, `seo.llms_note` | [`21` §9](../spec/21-engine.md#llmstxt) |
| 301 и 410 | `redirect_from` страниц и `gone` в `site.yaml`, сразу в конфиг nginx | [`21` §9](../spec/21-engine.md#redirects) |
| закрытая дев-сборка | без `--env prod`: `noindex` на всём, `Disallow: /`, без счётчиков | [`23`, «Версия движка и окружение сайта»](../spec/23-distribution.md#версия-движка-и-окружение-сайта--разные-вещи) |

## Что заполняете вы

**На каждой странице** — группа 1 SEO-блока:

- `title` — до 60 знаков, для выдачи. Суффикс сайта добавится сам;
- `h1` — для того, кто страницу уже открыл. Не копия `title`;
- `description` — до 155 знаков: что человек получит на странице;
- группа 2 «ключевые запросы» — движок её не читает, это рабочая записка: один интент — одна страница. Два файла с одним основным запросом — сигнал, что их надо слить.

Остальные группы — по надобности: своя картинка для соцсетей (3), уточнение разметки (5), картинка в каталоге и `alt` к ней (6), дата публикации, `noindex` (7), старые адреса (8).

**Один раз на сайт** — в `site.yaml`:

```yaml
site:
  domain: example.com
  name: Мастерская
seo:
  title_suffix: " — Мастерская"
  og_default_image: media/og/default.jpg
  llms_txt: true
  llms_note:                 # факты о сайте для нейросетей, по языкам
    uk: |
      Телефон для записи: …
contact: { phone: "…", city: "…" }
organization: { name: "…" }
schema:
  entity:                    # сквозной узел: кто стоит за сайтом
    "@type": Organization
    name: "{{ organization.name }}"
    telephone: "{{ contact.phone }}"
analytics:
  ga4: G-XXXXXXX
```

`{{ … }}` в `schema` — подстановки из того же `site.yaml`: адрес и телефон живут в одном месте и не расходятся между вёрсткой и разметкой. → [`20` §5, «Блок schema»](../spec/20-data-contract.md#блок-schema-разметка-без-дублирования-данных)

**Цены в разметке** запрещены по умолчанию (`E020`): если сайт не показывает стоимость на страницах, она не должна утечь в JSON-LD. Разрешить — `seo.allow_prices: true`.

## Языки

- Перевод — файл с тем же именем в папке языка; hreflang и переключатель языков появятся сами.
- У перевода может быть свой адрес (`slug`) — связь держится на имени файла.
- Один язык — нет hreflang, нет языковых карт и `llms-<язык>.txt`: лишнее не генерируется.
- Нет перевода — в отчёте предупреждение, в переключателе язык погашен; ссылки на такую страницу с других языков ведут на версию языка по умолчанию.
- Основной язык пуст — боевая сборка остановится (`E021`).

## Переезд со старого сайта

Цель — ни один проиндексированный адрес не должен отдать 404.

1. **Выгрузите старые адреса** — из карты сайта, Search Console, логов.
2. **Адрес переехал** — впишите его в SEO-блок новой страницы:

   ```yaml
   redirect_from:
     - /старая-страница/
     - /%D1%81%D1%82%D0%B0%D1%80%D0%B0%D1%8F/
   ```

   Кириллица и percent-encoding нормализуются: обе формы выше — один адрес, 301 сработает на любую, со слешем и без.
3. **Адреса больше нет** — в `gone` в `site.yaml`. Сервер ответит 410, и поисковик выкинет адрес быстрее, чем после 404:

   ```yaml
   gone:
     - /sample-page/        # ровно этот адрес
     - /wp/*                # всё под /wp/
     - /?p=*                # главная с параметром p
   ```

4. **Соберите.** Движок проверит, что старый адрес не совпадает с живой страницей, не ведёт в два места и не образует цепочку (`E009`), а 410 не пересекается со страницами и редиректами (`E022`).
5. **Проверьте на образе:** `scripts/site.sh <сайт> smoke prod` поднимает nginx и проверяет ответы 200, 404, каждый 301 и каждый 410 — [06 · Сборка и выкладка](06-deploy.md).

Подробно: [`20` §2, «Старые адреса»](../spec/20-data-contract.md#старые-адреса-кириллица-и-percent-encoding), [`22` §6](../spec/22-deploy.md#6-переезд-с-существующего-сайта).

## Перед выкладкой

```bash
heron build мой-сайт --env prod --strict
```

`--strict` превращает предупреждения в ошибки: битая ссылка, картинка без `alt`, незаполненная обязательная связь не уедут в прод. Отчёт сборки считает страницы по типам разметки — видно, что JSON-LD доехал до всех.
