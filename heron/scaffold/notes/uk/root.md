# {name}

Контент сайту на рушії [HERON](https://github.com/FMSTM/HERON). Тут лише
контент: тексти, медіа, тема, конфігурація. Збиранням, оточеннями та
пакуванням в образ займається HERON — ні Dockerfile, ні compose, ні `.env`
у цій теці немає і бути не повинно.

## З чого почати

`site.yaml` — єдина точка правди про сайт: домен, мови, тема, меню, версія
рушія. Структура тек іде за конфігом, а не навпаки: дописали мову в
`languages`, виконали `init` — під неї з'явилися `content/<мова>/`
і `theme/i18n/<мова>.yaml`.

Паролі й токени в `site.yaml` не пишуть: збирання статичне, і все, що воно
бачить, може опинитися в HTML.

## Що де лежить

| Тека | Що всередині |
|---|---|
| `content/<мова>/` | сторінки в markdown, шлях файлу = адреса сторінки |
| `media/` | усе, що показує контент: зображення, відео, документи |
| `theme/` | як сайт виглядає: шаблони, стилі, рядки інтерфейсу |
| `data/` | наскрізні довідники в yaml, доступні шаблонам як `data.<ім'я>` |
| `static/` | файли, які мусять лежати за точною адресою |
| `plugins/` | розширення збирання для цього сайту |

У кожній теці лежить `heron-readme.md` — коротка записка про те, що класти
туди й чого не класти. Рушій ці файли не помічає й у сайт не тягне.

## Порядок роботи

З теки HERON:

```bash
./scripts/site.sh {slug} init          # теки наздоганяють site.yaml
./scripts/site.sh {slug} build dev     # зібрати
./scripts/site.sh {slug} serve dev     # подивитися на localhost:8080
./scripts/site.sh {slug} stop  dev
```

Контенту може не бути зовсім — порожній сайт збирається й віддає robots.txt
і мапу сайту.
